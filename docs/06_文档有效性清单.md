# 文档有效性清单

> 更新日期：2026-08-26。所有旧文档均保留。本页的作用不是删除历史，而是防止接手人把计划、事故或特定集群部署说明误当成当前事实。

## 1. 判定规则

| 级别 | 含义 | 使用方式 |
|---|---|---|
| A 必读 | 当前维护口径 | 接手和排查从这里开始 |
| B 方法参考 | 仍有解释价值，但可能早于最新修复 | 理解算法，参数和实现必须回查当前代码 |
| C 历史记录 | 解释曾经的方案、事故或修复过程 | 只用于追溯，不作为运行说明 |
| D 不适用/待实现 | 面向旧设备、另一实验，或文档描述的代码当前不存在 | 不用于当前 BACE 运行 |
| U 上游文档 | 迁入依赖本身的 README | 只在维护相应上游模块时阅读 |

## 7. GitHub 不会出现的本地文档

`.gitignore` 排除了 `target/`、`experiments/` 和 `ICLR2027/`。这些目录可能含更新日期更晚的临时分析、图表或草稿，但它们不是公开仓库的稳定接口。若其中结论需要交接，应先用当前代码/artifacts 复核，再摘要进入 `docs/01` 或对应 A 级文档，不要要求接手人依赖一个 GitHub 中不存在的路径。

例外是：`target/BACE_vs_GiGPO_150step_TensorBoard对比分析_2026-08-27.md` 已被明确纳入 GitHub，级别为 **B（经验分析）**。它使用单 seed、不同 GPU/并行参数的历史 run，适合提出假设，不适合单独作因果或系统效率结论。`target/` 其余内容仍不纳入版本库。

## 8. 防止文档再次失序

以后每次代码或实验状态发生实质变化时：

1. 先更新 `docs/01` 的证据、限制和下一步；
2. 若新增文档，在本清单登记级别和用途；
3. 运行命令只放设备无关示例，集群专用命令放部署历史；
4. “计划”“已实现”“单测通过”“GPU smoke 通过”“长跑完成”必须明确区分；
5. 结果必须注明 run name、源码 commit/manifest、数据和验收状态；
6. 不修改或删除旧记录来制造一致性，用本清单标记其历史边界。
