# 运行环境安装清单

> 本页是可逐项勾选的交接清单。命令细节见 [新设备安装与首次运行](02_新设备安装与首次运行.md)，验收标准见 [验证验收与故障排查](05_验证验收与故障排查.md)。不要把原 RWTH Slurm 账号、分区或绝对路径当成新设备要求。

## 1. 主机和 GPU

- [ ] Linux x86_64；当前已知基线为 NVIDIA CUDA GPU。
- [ ] `nvidia-smi` 正常，已记录 driver、GPU 型号、显存和可见卡数。
- [ ] 多卡机器已验证 NCCL/P2P；scheduler 或容器允许足够的 CPU、PID 和共享内存。
- [ ] 已记录 CUDA module/toolkit；它必须与 PyTorch wheel 和 driver 兼容。

已知 H100 基线：Python 3.12、PyTorch 2.8、vLLM 0.11.0、FlashAttention 2.7.4.post1。其他 GPU 可以使用，但必须重新完成全部门禁。

## 2. 获取源码和记录身份

```bash
git clone https://github.com/XYR222/BACE.git
cd BACE
git switch <交接分支>
git rev-parse HEAD
git status --short --branch
```

- [ ] 已保存分支名和 commit SHA。
- [ ] 工作树干净；本地补丁另存并记录，不能只写“最新版”。

## 3. Python 环境

自动安装入口：

```bash
BACE_GPU_ENV_NAME=bace-gpu bash deploy/gpu/install_gpu_env.sh
conda activate bace-gpu
python -m pip install pytest
```

安装器读取：

- `deploy/gpu/environment.yml`：Python 3.12、pip、git/git-lfs、ninja、packaging；
- `deploy/gpu/requirements-gpu.lock.txt`：vLLM、torchvision/torchaudio、ALFWorld、NumPy 等已知基线；
- `deploy/gpu/install_gpu_env.sh`：单独编译 FlashAttention，并 editable 安装 `verl-agent-src`。

- [ ] `python -m pip check` 通过。
- [ ] `torch`、`ray`、`vllm`、`flash_attn`、`transformers`、`alfworld` 可导入。
- [ ] `python -c 'import recipe, agent_system, verl; print(recipe.__file__, agent_system.__file__, verl.__file__)'` 指向当前 clone，而不是旧 AFH/verl-agent editable checkout。
- [ ] `torch.cuda.is_available()` 为 true，GPU 数与预期一致。
- [ ] 保存 `python -m pip freeze > pip_freeze.txt`。

安装文件不是完整系统镜像；若目标设备不兼容这组 wheel，应先选择适配硬件的 PyTorch/vLLM/FlashAttention 组合，再安装本仓库。不要只替换其中一个二进制包后跳过 ABI 检查。

## 4. 仓库外资产

- [ ] 模型：`Qwen/Qwen2.5-1.5B-Instruct`，记录 revision 和 SHA-256。
- [ ] 模型含 `config.json`、tokenizer 文件以及单权重文件，或 index 中引用的全部 safetensors shards。
- [ ] ALFWorld 0.4.2 数据含 logic、train、valid_seen、valid_unseen。
- [ ] train parquet 为 16 行，validation parquet 为 128 行，或明确记录新的数据版本。
- [ ] parquet schema 至少含 `answer, data_source, prompt, ability, extra_info`。
- [ ] 模型、ALFWorld 和 parquet 均放在 Git 仓库外，并有 checksum manifest。

建议设置：

```bash
export BACE_ROOT="$PWD"
export MODEL_PATH=/path/to/Qwen2.5-1.5B-Instruct
export ALFWORLD_DATA=/path/to/alfworld
export TRAIN_FILE=/path/to/train.parquet
export VAL_FILE=/path/to/test.parquet
export BACE_EXP_ROOT=/path/to/bace-runs
export GPU_COUNT=1
export RAY_NUM_CPUS=16
```

## 5. 安装后门禁

按顺序执行，前一层未通过不要进入下一层：

- [ ] GPU/模型/ALFWorld preflight 的 `ok=true`。
- [ ] parquet 行数、schema 和 checksum 正确。
- [ ] CPU 回归退出码 0；准确 collect 数以当前 commit 和 `docs/01` 为准，不沿用旧常数。
- [ ] dry-run 的 resolved command 只包含新设备路径。
- [ ] dry-run 明确显示 Exact/staged/packed、selected-worker、`main_reuse`、active-root 和 `stable_v1`。
- [ ] 一步 smoke 达到 global step 1、退出码 0、summary complete、trace `ok=true`。
- [ ] 新进程恢复到 step 2，history、dataloader、optimizer 和 global step 连续。
- [ ] 至少一个真实 branch step 验证 request、Replay、selected-worker 和执行成本守恒。
- [ ] 多步稳定性门禁无 OOM、Ray/PID 泄漏或 checkpoint 异常。

CPU 回归命令：

```bash
cd "$BACE_ROOT/verl-agent-src"
pytest -q tests/bace_gigpo tests/trainer/ppo/test_metric_utils.py
```

若复用已有环境，其 editable install 可能仍指向另一份 `AFH`/verl-agent。应重新执行 `pip install -e "$BACE_ROOT/verl-agent-src"`；临时诊断可用 `PYTHONPATH="$BACE_ROOT/verl-agent-src"`，但不能把路径污染造成的 collection error 记成代码回归失败。

## 6. 新实验推荐配置边界

- 方法默认保持 `B=8, R_min=2, L_max=2`、Exact Batch-ERV、Beta(0.2,1.8)、forgetting 0.8、threshold 0.005。
- 正式 acquisition/credit 默认保持 `pairwise.mode=full`、`local_credit_mode=occurrence`；fixed/stopping/action_mean 是独立消融。
- 新实验推荐 `branch_pool_mode=main_reuse`、`root_active_executor=true`、`tie_break_identity_mode=stable_v1`。
- 4×H100 已验证 actor/log-prob micro batch `16/16`；`32/32` 曾在 PPO backward OOM。其他设备重新 profile。
- `diagnostic_rmin2_to4` 只用于独立输出目录的受控诊断，不是普通 resume 或正式默认。
- checkpoint 至少保留最近两份时应先确认存储；无论 retention 数量如何，都不得轮转其他实验 root 的源 checkpoint。

## 7. 不应安装或复制的内容

- [ ] 不复制旧 conda 环境目录作为跨机器安装方案。
- [ ] 不复制 Ray session、`/tmp`、core dump 或旧 Slurm dependency chain。
- [ ] 不把模型、parquet、checkpoint、TensorBoard、密钥或个人 `.env` 提交到 GitHub。
- [ ] 不直接运行 `examples/bace_gigpo/*.sbatch`，除非已经逐项替换目标平台的路径、资源和 scheduler 配置。

安装完成后，应把 commit、资产 checksum、pip freeze、preflight、resolved command 和门禁报告作为同一次运行的 metadata 保存。
