# 新设备安装与首次运行

## 1. 支持范围

当前现成运行层面向 Linux x86_64 + NVIDIA CUDA。原开发环境使用 H100、Python 3.12、PyTorch 2.8、vLLM 0.11.0 和 FlashAttention 2.7.4.post1。

这是一套已知环境基线，不代表只能使用 H100。A100 或其他 CUDA GPU 可以先运行，但必须重新验证：

- NVIDIA driver 与 PyTorch CUDA build；
- GPU compute capability 与 FlashAttention；
- vLLM/PyTorch/transformers ABI；
- bf16 支持；
- 单卡显存和 micro batch；
- 多卡 NCCL 和 tensor parallel。

CPU、AMD GPU、Apple Silicon 或 NPU 不能直接使用通用 CUDA launcher。仓库里的旧 NPU 脚本是历史实现，不应被当成当前主线保证。

## 2. Clone 与版本记录

```bash
git clone https://github.com/XYR222/BACE.git
cd BACE
git status --short --branch
git rev-parse HEAD
```

每次实验都记录具体 commit SHA。不要只记录“main 最新版”。

## 3. 建立 Python/CUDA 环境

### 3.1 与已知基线兼容的 NVIDIA 机器

确保 `nvidia-smi` 正常，再运行：

```bash
BACE_GPU_ENV_NAME=bace-gpu bash deploy/gpu/install_gpu_env.sh
conda activate bace-gpu
python -m pip install pytest
```

该安装器会：

- 创建 Python 3.12 conda 环境；
- 安装 vLLM 0.11.0 及匹配的 PyTorch；
- 安装 ALFWorld 0.4.2；
- 编译 FlashAttention 2.7.4.post1；
- editable 安装 `verl-agent-src/`。

如果目标设备不能使用上述版本，不要强行复用 wheel。先建立与该设备匹配的 PyTorch/vLLM/FlashAttention 组合，再执行：

```bash
python -m pip install -e ./verl-agent-src
python -m pip install pytest
```

并保存完整 `pip freeze`。

### 3.2 基本导入检查

## 4. 准备外部资产

推荐在仓库外保存大资产，再通过环境变量引用。也可以建立以下默认布局：

```text
BACE/
  assets/
    models/Qwen2.5-1.5B-Instruct/
    alfworld/
    training_data/alfworld_text_16_64/
      train.parquet
      test.parquet
```

主实验模型是官方 `Qwen/Qwen2.5-1.5B-Instruct`。模型目录至少应包含：

- `config.json`；
- tokenizer 配置和词表文件；
- 单文件 `model.safetensors`，或 `model.safetensors.index.json` 与索引中的全部 shard。

ALFWorld 目录至少应包含：

```text
logic/alfred.pddl
logic/alfred.twl2
json_2.1.1/train/
json_2.1.1/valid_seen/
json_2.1.1/valid_unseen/
```

有网络时可参考：

```bash
SOURCE_ENV=bace-gpu \
TARGET_ENV=bace-gpu \
ASSET_ROOT="$PWD/assets" \
bash deploy/gpu/setup_alfworld_and_assets.sh
```

注意该脚本不会生成训练 parquet。

## 5. 设置设备无关的运行变量

下面的示例不依赖 RWTH 路径：

```bash
export BACE_ROOT="$PWD"
export MODEL_PATH="/path/to/Qwen2.5-1.5B-Instruct"
export ALFWORLD_DATA="/path/to/alfworld"
export TRAIN_FILE="/path/to/train.parquet"
export VAL_FILE="/path/to/test.parquet"
export BACE_EXP_ROOT="/path/to/bace-runs"

export CUDA_VISIBLE_DEVICES=0
export GPU_COUNT=1
export RAY_NUM_CPUS=16

export OMP_NUM_THREADS=1
export OMP_THREAD_LIMIT=1
export MKL_NUM_THREADS=1
export OPENBLAS_NUM_THREADS=1
export NUMEXPR_NUM_THREADS=1
export RAYON_NUM_THREADS=1
export MALLOC_ARENA_MAX=2
```

不要把接手设备的路径重新硬编码进主线 Python 代码。优先使用上述环境变量或 Hydra override。

## 6. 资产与 GPU preflight

```bash
python deploy/gpu/check_gpu_environment.py \
  --expected-gpus "$GPU_COUNT" \
  --model-path "$MODEL_PATH" \
  --alfworld-data "$ALFWORLD_DATA" \
  --output /tmp/bace-preflight.json
```

`ok` 必须为 `true`。非 H100 会显示 warning；这本身不是失败，但接下来必须做真实 smoke。

另外检查 parquet：

```bash
python - <<'PY'
import os
import pyarrow.parquet as pq

for name in ("TRAIN_FILE", "VAL_FILE"):
    path = os.environ[name]
    table = pq.read_table(path)
    required = {"answer", "data_source", "prompt", "ability", "extra_info"}
    missing = required.difference(table.column_names)
    print(name, path, "rows=", table.num_rows, "missing=", sorted(missing))
    assert not missing
PY
```

## 7. 先跑完整 CPU 回归

```bash
cd "$BACE_ROOT/verl-agent-src"
pytest -q tests/bace_gigpo tests/trainer/ppo/test_metric_utils.py
```

交接时的参考结果是 `126 passed`。如果数量发生变化，以当前测试收集数和 Git commit 为准；任何失败都应先处理，不要进入 GPU 长训练。

## 8. Dry-run

通用入口是：

```text
examples/gigpo_trainer/run_bace_alfworld_gpu.sh
```

执行：

```bash
cd "$BACE_ROOT/verl-agent-src"
export BACE_RUN_NAME=handoff_dry_run

DRY_RUN=1 bash examples/gigpo_trainer/run_bace_alfworld_gpu.sh \
  algorithm.bace.tie_break_identity_mode=stable_v1 \
  ray_init.num_cpus="$RAY_NUM_CPUS" \
  trainer.total_training_steps=1
```

检查：

```text
$BACE_EXP_ROOT/run_metadata/handoff_dry_run/resolved_command.sh
$BACE_EXP_ROOT/run_metadata/handoff_dry_run/preflight.json
$BACE_EXP_ROOT/run_metadata/handoff_dry_run/source_manifest.sha256
```

resolved command 中应出现正确的本地模型、parquet、GPU 数、Exact Batch-ERV、packed、selected-worker 和 `stable_v1`。

## 9. 一步最小 smoke

不要使用含 RWTH 绝对路径的 H100 wrapper。直接给通用入口提供小配置：

```bash
cd "$BACE_ROOT/verl-agent-src"

export BACE_RUN_NAME=handoff_one_step_smoke
export TRAIN_DATA_SIZE=1
export VAL_DATA_SIZE=1
export GROUP_SIZE=2
export BACE_TOTAL_EPOCHS=1
export ENV_MAX_STEPS=2
export MAX_RESPONSE_LENGTH=64
export ACTOR_MICRO_BATCH=1
export LOGPROB_MICRO_BATCH=1
export PPO_MINI_BATCH=2
export ROLLOUT_TP=1
export GPU_MEMORY_UTILIZATION=0.25
export MAX_NUM_BATCHED_TOKENS=4096
export MAX_NUM_SEQS=8
export SAVE_FREQ=-1
export TEST_FREQ=-1
export LOGGER_BACKENDS="['console']"

bash examples/gigpo_trainer/run_bace_alfworld_gpu.sh \
  algorithm.bace.tie_break_identity_mode=stable_v1 \
  algorithm.bace.total_leaf_budget=2 \
  algorithm.bace.min_natural_roots=1 \
  algorithm.bace.max_branches_per_anchor=1 \
  actor_rollout_ref.model.lora_rank=8 \
  actor_rollout_ref.model.lora_alpha=8 \
  actor_rollout_ref.actor.fsdp_config.param_offload=true \
  actor_rollout_ref.actor.fsdp_config.optimizer_offload=true \
  actor_rollout_ref.rollout.enforce_eager=true \
  ray_init.num_cpus="$RAY_NUM_CPUS" \
  trainer.total_training_steps=1
```

验收：

- 进程退出码为 0；
- 出现 `training/global_step:1`；
- 至少一个 `step_*/summary.json` 为 `status=complete`；
- trace validation JSON 为 `ok=true`；
- manifest 记录 `batch_erv_exact`、packed 和 selected-worker 配置。

两步 horizon 可能形成不了结构 anchor 或 branch，这不是启动链路失败。真实 branch 执行应在后续较长 smoke 中验证。

## 10. 从 smoke 进入正式实验

正式训练前至少再完成：

1. step 1 保存 checkpoint；
2. 退出进程；
3. 新进程从同一 checkpoint 目录恢复；
4. 完成 step 2；
5. 验证 BACE history 连续；
6. 验证 ALFWorld task rotation；
7. 验证至少一个 branch step 的 selected-worker 指标。

目标设备如何排队、容器化或提交作业属于部署层。只要为进程提供同样的环境变量、资产和持久化输出目录，就不需要复用原 RWTH Slurm 链。
