# 资产与实验结果迁移清单

## 1. GitHub 已包含什么

GitHub 主要包含：

- BACE/Exact Batch-ERV 源码；
- 迁入的 verl-agent 必需子集；
- ALFWorld 环境源码子集；
- 单元和专项测试；
- 通用 CUDA launcher；
- 原集群脚本作为参考；
- 方法、问题和交接文档。

## 2. GitHub 明确不包含什么

`.gitignore` 排除了：

- `experiments/`；
- `ICLR2027/`；
- `__pycache__/` 和 `*.pyc` 机器缓存（分析目录中的人写文档和脚本可以纳入 Git）；
- 模型和 `model_down/`；
- `data/` 和所有 parquet；
- checkpoint、PyTorch 权重和 optimizer 状态；
- TensorBoard、wandb、日志和 core dump；
- conda/venv 环境；
- 本机 `.env`、credentials 和密钥。

因此“clone 成功”不等于“可以直接训练”。

## 3. 从零开始新实验时需要的外部资产

### 3.1 模型

主模型：

```text
Qwen/Qwen2.5-1.5B-Instruct
```

建议移交以下信息：

- Hugging Face repo ID 和 revision；
- 本地目录的 SHA-256 manifest；
- `config.json`；
- tokenizer 全部文件；
- `model.safetensors`，或 index 和全部 shards。

不要把模型权重提交进本仓库。

### 3.2 ALFWorld

建议重新通过 ALFWorld 0.4.2 下载，或复制完整 cache。至少校验：

```text
logic/alfred.pddl
logic/alfred.twl2
json_2.1.1/train/
json_2.1.1/valid_seen/
json_2.1.1/valid_unseen/
```

记录 ALFWorld package 版本、数据目录清单和关键文件 checksum。

### 3.3 parquet

原开发数据：

- train：16 行；
- validation：128 行；
- schema：`answer, data_source, prompt, ability, extra_info`。

GitHub 没有生成脚本。最稳妥的交接方式是单独传输这两个 parquet，并提供：

```bash
sha256sum train.parquet test.parquet
```

如果接手方重新生成，必须视为新的数据版本，并记录：

- 生成脚本 commit；
- 原始数据来源；
- split 和抽样方法；
- row count 与 schema；
- SHA-256。

## 4. 已完成 150-step 结果的迁移状态

原开发环境存在完整 run：

```text
bace_alfworld_qwen2_5_1_5b_exact_rotation_fix_seed0
```

它已完成 step 150，当前保留 step 145/150 checkpoint，并有约 114 GiB 的实验目录。GitHub 只记录摘要，不上传这些大文件。若接手方需要审计曲线、复跑 trace 或从 step 150 继续，必须另行复制完整实验目录并校验 checksum。

由于该 run 的 metadata 没有可用 Git commit SHA，只能同时移交 `source_manifest.sha256`、`working_tree.patch`、`index.patch`、`resolved_command.sh` 和依赖记录；不能用当前 GitHub HEAD 替代当时源码身份。

## 5. 要继续旧训练时必须额外迁移什么

仅复制 actor 权重不足以恢复 dynamic BACE。必须复制整个 run 的 checkpoint 根目录，包括：

```text
latest_checkpointed_iteration.txt
global_step_<N>/
  actor/
  critic/                 # 若该配置启用
  data.pt
  bace_collector_state.json
  ...其他框架状态
```

实际目录名称以 checkpoint 内容为准，不要手工挑选文件。传输后校验目录级 SHA-256 manifest。

同时建议迁移：

- `bace_artifacts/<run_name>/`；
- `run_metadata/<run_name>/`；
- `trace_validation/<run_name>/`；
- `rollout_trajectories/<run_name>/`；
- TensorBoard event files；
- 原始 stdout/stderr；
- 当次 `pip_freeze.txt`；
- `source_manifest.sha256`；
- `resolved_command.sh`；
- GPU/CPU/cgroup 监控数据。

没有这些信息时，可以加载模型做新实验，但不能声称无缝延续原 run。

## 6. 推荐的传输目录

Git 仓库和大资产分开：

```text
handoff/
├── BACE/                         # git clone
├── assets/
│   ├── models/Qwen2.5-1.5B-Instruct/
│   ├── alfworld/
│   └── data/text/
│       ├── train.parquet
│       └── test.parquet
├── runs/                         # 可选：旧实验
│   └── <run_name>/
└── SHA256SUMS
```

在新设备上通过环境变量连接这些目录，不要改 Python 源码：

```bash
export MODEL_PATH=/new/path/assets/models/Qwen2.5-1.5B-Instruct
export ALFWORLD_DATA=/new/path/assets/alfworld
export TRAIN_FILE=/new/path/assets/data/text/train.parquet
export VAL_FILE=/new/path/assets/data/text/test.parquet
export BACE_EXP_ROOT=/new/path/runs
```

## 7. 不建议直接迁移的内容

- 整个 conda 环境目录：路径、driver 和 binary ABI 很容易失效；优先重建。
- Ray session 和 `/tmp` 内容：不是可移植状态。
- core dump：体积大，通常只对原二进制和原节点有效。
- 旧 Slurm job ID、dependency chain 和 allocation：新设备无法复用。
- 只有 symlink 没有实际目标的大资产目录。
