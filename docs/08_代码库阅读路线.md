# 代码库阅读路线

> 目标：让第一次接触本仓库的人用最少时间找到当前主线，而不是被旧脚本、兼容分支和迁入的完整 verl-agent 框架淹没。

## 1. 先建立三个边界

### 仓库不是纯 BACE 小项目

`verl-agent-src/` 是迁入的训练框架，BACE 只是在其中增加 collector、advantage、Replay、checkpoint 和运行入口。阅读时不要从整个 `verl/` 目录逐文件开始。

### 配置默认不等于主线

`verl/trainer/config/ppo_trainer.yaml` 为兼容多种算法保留：

```text
bace.enabled=false
variant=legacy
topology=fixed
staged_root_batching=sequential
branch_execution_mode=legacy_dense
acquisition=erv
tie_break_identity_mode=legacy_uuid
```

当前 Exact 主线由 `examples/gigpo_trainer/run_bace_alfworld_gpu.sh` 显式覆盖。判断一次 run 走了什么逻辑，应看 resolved command 和 artifact manifest，不能只看 YAML。

### 原集群脚本不是代码入口

`examples/bace_gigpo/*.sbatch`、H100 wrapper、NPU/A100 脚本是部署或历史对照。理解算法从通用 GPU launcher 和 Python 调用链开始。

## 2. 推荐阅读顺序

### 第 1 层：运行合同

1. `examples/gigpo_trainer/run_bace_alfworld_gpu.sh`
2. `verl/trainer/config/ppo_trainer.yaml` 中的 `algorithm.bace`
3. `verl/trainer/main_ppo.py` 中创建 collector 的分支

先回答：BACE 是否启用、env rollout 数为什么等于 leaf budget、branch env pool 如何创建、哪些 override 构成主线。

### 第 2 层：一次 step 的编排

阅读 `recipe/bace_gigpo/rollout_collector.py`，建议按以下方法跳转：

1. `__init__`：组合合法性和对象选择；
2. `multi_turn_loop`：总流程；
3. `_collect_exact_batch_dynamic_roots_packed`：Exact roots 与 capacity correction；
4. `_execute_round`：request chunking；
5. `_execute_chunk_selected`：selected-worker origin transaction；
6. `_collect_suffixes_selected`：active suffix 压缩；
7. `state_dict/load_state_dict`：checkpoint contract；
8. `save_training_diagnostics`：advantage 后 artifact finalize。

不要从 2,000 多行文件的中间顺序阅读；先用上述调用链建立骨架。

### 第 3 层：方法核心

按数据流阅读：

```text
root_store.py
  -> types.py
  -> competence.py
  -> topology.py
  -> anchor_index.py
  -> posterior.py
  -> batch_erv.py
  -> coordinator.py
```

对应职责：

| 文件 | 主要职责 | 首要入口 |
|---|---|---|
| `root_store.py` | 从 DataProto 还原 natural root event logs | `build_root_event_logs` |
| `types.py` | root、event、anchor、request、result 数据合同 | dataclasses |
| `competence.py` | lagged family history、Beta prior、state persistence | `CompetenceHistory` |
| `topology.py` | 每 task 的 R/Q 规划和 capacity correction | `ExactBatchTopologyPlanner` |
| `anchor_index.py` | frozen roots 到 structural anchors/origins | `AnchorIndex` |
| `posterior.py` | local Beta posterior 和旧 ERV 工具 | `BetaPosterior` |
| `batch_erv.py` | Exact finite-sum value、local design、global DP | `ExactBatchErvEngine` |
| `coordinator.py` | 将 Exact allocation 冻结成 ReplayRequest | `ExactBatchErvCoordinator` |

### 第 4 层：Replay

```text
recipe/bace_gigpo/replay/alfworld.py
recipe/bace_gigpo/replay/validator.py
agent_system/environments/env_manager.py
agent_system/environments/env_package/alfworld/envs.py
```

先区分两阶段校验：

1. prefix replay 后验证到达正确的 pre-action state；
2. 执行复制 origin action 后验证 transition。

`env_manager.py` 的 dense `replay(requests)` 对请求数有 pool capacity 限制；当前 collector 在调用前已在 `_execute_round` 分块。selected-worker 路径使用 `replay_selected`、`step_selected` 和 `get_observations_selected`。

### 第 5 层：advantage 与 PPO

```text
recipe/bace_gigpo/advantage.py
verl/trainer/ppo/ray_trainer.py::compute_advantage
verl/trainer/ppo/ray_trainer.py::fit
```

关注 metadata：

- `uid`：task group；
- `traj_uid`：natural root 或 branch trajectory；
- `anchor_obs`：GiGPO step group；
- `action_identity`：action-aware credit 和审计；
- `source_type`：root / branch_origin / branch_suffix；
- `occurrence_id`、`leaf_id`：trace lineage。

### 第 6 层：artifact 与 checkpoint

```text
recipe/bace_gigpo/artifacts.py
recipe/bace_gigpo/validate_trace.py
verl/trainer/ppo/ray_trainer.py::_save_checkpoint
verl/trainer/ppo/ray_trainer.py::_load_checkpoint
```

artifact 是逐 step 可解释证据，checkpoint 是可继续训练的状态；两者不可互相替代。

## 3. 运行时调用链

```text
run_bace_alfworld_gpu.sh
  -> python -m verl.trainer.main_ppo
  -> main_ppo.TaskRunner.run
  -> 创建 ALFWorld envs / branch_envs
  -> BaceTrajectoryCollector(...)
  -> RayPPOTrainer.fit
       -> collector.set_step(global_step)
       -> collector.multi_turn_loop(...)
       -> compute_step_discounted_returns
       -> reward / invalid penalty / log-probs
       -> compute_bace_gigpo_advantage
       -> collector.save_training_diagnostics
       -> actor update
       -> validation / checkpoint
```

验证路径 `is_train=False` 会调用基础 `TrajectoryCollector`，不执行 BACE branch acquisition。因此 validation 衡量当前 policy 的 natural task 表现，而不是包含 branch 的训练 batch 表现。

## 4. Exact root/branch 数据流

```text
gen_batch 中每个 task slot
  -> 初始化 family-history topology state
  -> packed wave 生成计划数量的 natural roots
  -> build_root_event_logs
  -> AnchorIndex + local Batch-ERV design
  -> information capacity 不足的 task：Q--, R++，再生成 root
  -> finalize TopologyPlan
  -> ExactBatchErvCoordinator.initialize
  -> quota-aware global allocation
  -> 冻结 ReplayRequest 列表
  -> 按 replay_capacity 分 chunk
  -> selected worker prefix replay + origin transition + suffix
  -> root/origin/suffix DataProto concat
  -> advantage + PPO
  -> natural roots 更新 family history
```

## 5. 核心数据对象之间的映射

| 对象 | 创建处 | 消费处 | 不变量 |
|---|---|---|---|
| `RootEventLog` | `root_store.py` | topology、anchor index、trace | events 按真实自然轨迹排列 |
| `TaskTopology` | `topology.py` | collector、coordinator、metrics | 每 task `R+Q=B` |
| `AnchorRecord` | `anchor_index.py` | Batch-ERV coordinator | 同 task、同 pre-action obs、至少 2 actions |
| `ReplayRequest` | `coordinator.py` | Replay adapter、executor | origin token/transition identity 已冻结 |
| `ReplayResult` | validator | collector retry/fail-fast | 恢复错误与普通 reward 分离 |
| training `DataProto` | collector concat | reward/advantage/PPO | source lineage 和 token arrays 对齐 |
| collector state | checkpoint | resume | global step 和参数签名一致 |

## 6. 修改需求应该落在哪里

| 需求 | 首选修改点 | 必须补的测试 |
|---|---|---|
| 改 family prior/history | `competence.py`、collector signature | history round-trip、resume mismatch、cold start |
| 改 R/Q 规则 | `topology.py` | budget、capacity convergence、history isolation |
| 改 anchor eligibility/identity | `anchor_index.py` | invalid identity、stable identity、Replay origin |
| 改 Batch-ERV 数学 | `batch_erv.py` | 小规模 Cartesian oracle、tie、性能、capacity |
| 改 branch 选择 | `coordinator.py` | frozen quota、origin reservation、determinism |
| 改执行并行方式 | collector + env manager | chunking、selected slots、cost conservation |
| 改 advantage | `advantage.py` + trainer integration | 长度、invalid penalty、normalization、components |
| 改 checkpoint | trainer + collector state | 缺失/损坏/签名/跨进程轮转 |
| 改 trace schema | `artifacts.py` + validator | round-trip、截断/失败、record counts |

## 8. 排查问题的快捷路径

### 没有 branch

依次查：family readiness → planned Q → structural anchors → information capacity → capacity correction → final Q。

### branch 数不对

查 `TopologyPlan.branch_quota_by_task`、coordinator diagnostic、`branch_execution_waves.jsonl` 和 summary record counts。Exact 模式不允许静默少执行。

### Replay mismatch

查 request 的 reset key、prefix、expected observation/action set，再查 origin transition 的 expected reward/done/post observation。不要先调 acquisition 参数。

### advantage 异常

先按 `source_type`、`uid`、`traj_uid`、`anchor_obs`、`action_identity` 检查分组和 token mask，再检查 reward/penalty。不要只看最终 PPO loss。

### 恢复失败

同时检查 actor 目录、`data.pt`、`bace_collector_state.json`、tracker 和 parameter signature。不要伪造空 history。

## 9. 阅读时应忽略的噪声

- `__pycache__/` 和本地生成文件；
- 原集群 job ID、account、partition；
- 文件名带“最终版”但早于当前代码的设计稿；
- `frontier`、NPU、WebShop、reference GiGPO，除非任务明确涉及它们；
- 根目录 StateID 实现说明，其代码不在当前 tree；
- 只反映某次旧事故的日志结论。
