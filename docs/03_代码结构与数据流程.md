## 2. 一次训练 step 的主流程

```text
parquet prompts
  -> RayPPOTrainer
  -> BaceTrajectoryCollector
  -> 生成 natural roots
  -> task-level topology 规划 R/Q
  -> 从冻结 roots 建 AnchorIndex
  -> Exact Batch-ERV 选择 branch 请求
  -> active-root executor 跳过已完成 logical roots
  -> 按物理 pool capacity/cohort 映射 branch
  -> selected workers 恢复 origin 并执行 branch
  -> 合并 natural/branch trainable occurrences
  -> GiGPO-compatible advantage
  -> PPO update
  -> artifacts + checkpoint + history update
```

## 3. 输入数据

parquet 每一行代表一个训练 prompt/task slot。当前数据 schema 为：

```text
answer: string
data_source: string
prompt: list<struct<role: string, content: string>>
ability: string
extra_info: struct<split: string, index: int64>
```

当前原开发资产是 16 行 train、128 行 validation。数据文件只提供 prompt 元信息；真实 ALFWorld game 和 transition 来自 `ALFWORLD_DATA`。

## 4. Natural roots 与 topology

`BaceTrajectoryCollector` 是训练器调用的轨迹入口。Exact 主线为每个 task 维护独立状态：

- terminal-leaf budget `B`；
- natural root 数 `R`；
- branch quota `Q`；
- 要求 `R + Q = B`；
- `R >= R_min`；
- `Q` 受可执行 anchor capacity 限制。

`CompetenceHistory` 使用上一步以前的 family history 估计当前 task competence。当前 step 的 branch outcome 不回写 family history；history 只从该 step 的 frozen natural roots 更新，避免 acquisition 行为污染 competence 定义。

关键代码：

```text
recipe/bace_gigpo/competence.py
recipe/bace_gigpo/topology.py
recipe/bace_gigpo/frontier.py
recipe/bace_gigpo/rollout_collector.py
```

## 5. Anchor 与 action identity

`AnchorIndex` 只从 frozen natural roots 建立。结构 anchor 要求：

- 同一 task；
- exact pre-action observation 相同；
- 至少两个 occurrence；
- 至少两个统计 action identity。

step 0 不作为 branch origin。`strict_identity` 将 action format validity、environment validity 和可复现 transition identity 分开记录，避免把所有 invalid action 粗暴合并。

关键代码：

```text
recipe/bace_gigpo/anchor_index.py
recipe/bace_gigpo/types.py
recipe/bace_gigpo/replay/validator.py
recipe/bace_gigpo/replay/alfworld.py
```

## 6. Exact Batch-ERV

每个 anchor 先根据 local Beta posterior 计算选 0 到 `L_max` 个 branch 的 Exact 价值和 tie-optimal local plans。随后全局 DP 在所有 anchor 间分配 task quota `Q`。

全局 DP 状态只保留：

```text
(已经处理的 anchor 数, 已分配 branch 数)
```

因此不会重新出现先枚举 `3^N` 再筛选 quota 的事故。tie sampling 按完整最优 allocation 的数量加权，而不是在压缩后的 DP predecessor 间错误地等概率抽样。

关键代码：

```text
recipe/bace_gigpo/batch_erv.py
recipe/bace_gigpo/coordinator.py
tests/bace_gigpo/test_batch_erv_exact.py
```

## 7. Replay 请求、分块与 selected-worker

Coordinator 先冻结完整请求集，包含：

- task、branch 和 request identity；
- origin occurrence；
- game/reset key；
- prefix actions；
- origin action 的原始 model response 和规范 identity；
- expected reward、done 和 post-action observation；
- remaining horizon。

collector 再依据物理 pool capacity 将请求映射到执行 cohort。`dedicated` 模式使用独立 Replay pool 并按其 `replay_capacity` 分块；推荐的 `main_reuse` 模式借用 main rollout pool 中对应 task 的 sibling slots，容量不足时仍安全回退为多个 cohort。两者都只是执行调度，不重新规划、不改变请求顺序、不重新采样 origin。

selected-worker 模式的执行顺序是：

```text
对当前 chunk 的 slots 做 prefix replay
  -> 校验到达 origin pre-action state
  -> 仅在这些 slots 执行复制的 origin action
  -> 校验 transition
  -> 只对仍 active 的 slots 生成 suffix
  -> retry 时只恢复失败 slot
```

如果一个 Exact chunk 最终有效 branch 数少于冻结请求数，代码会失败，而不是把较小 batch 当作成功。

natural root 也有两种物理执行模式：兼容路径会持续提交 dense packed rows；`root_active_executor=true` 会在每个 generation wave 前 gather 尚未 done 的 logical roots，并把输出 scatter 回原逻辑位置。必要的多卡 padding 不得创建假的环境 action、occurrence 或 lineage。

## 8. Trainable occurrence 与 advantage

训练批次区分：

- `natural`：natural-root occurrence；
- `branch_origin`：从 natural origin 复制 token、mask 和 rollout old log-prob；
- `branch_suffix`：branch 在 origin action 之后新生成的 occurrence。

当前主线 advantage 与 GiGPO macro/step 口径兼容：

```text
occurrence_advantage = macro_advantage
                     + step_advantage_w * local_advantage
```

invalid-action penalty 先进入 token rewards，再影响 macro return。GiGPO normalization 的均值和样本标准差使用 float64 临时统计，再转换回原 tensor dtype，降低大值/近零方差下的数值不稳定；最终 advantage 与 trace 仍按实际 float32 语义验收。validator 还会检查复制 origin 的 token/mask/old-log-prob 以及失败 branch 未进入训练批次。

关键代码：

```text

verl/trainer/ppo/ray_trainer.py
tests/bace_gigpo/test_advantage.py
tests/bace_gigpo/test_trainer_advantage_integration.py
```

## 9. Artifacts 与 trace

启用 artifacts 时，每个 step 使用独立目录：

```text
step_00000001/
  manifest.json
  roots.jsonl
  anchors.jsonl
  topology.jsonl
  branch_requests.jsonl
  replay_results.jsonl
  trainable_occurrences.jsonl
  posterior_snapshots.jsonl
  summary.json
```

同一步骤重试会使用 attempt suffix，避免覆盖旧的失败尝试。只有 finalize 成功后，`summary.json` 才应为 `status=complete`。

通用校验：

```bash
cd verl-agent-src
python -m recipe.bace_gigpo.validate_trace /path/to/bace_artifacts \
  --output /path/to/trace_validation.json
```

不要只看训练日志中的 loss。正式验收必须同时看 summary、trace validation 和运行 metadata。

## 10. Checkpoint 与恢复

checkpoint step 目录中的 actor 状态、optimizer、scheduler、RNG、dataloader 和 `bace_collector_state.json` 必须属于同一 global step。`latest_checkpointed_iteration.txt` 只能在所有状态成功落盘后更新。

恢复流程先校验并恢复 BACE state，再加载多 GiB actor/optimizer 和 dataloader 状态。这样签名不匹配会在修改训练器大状态前失败。dynamic BACE 非零恢复缺少 state 时应失败。

checkpoint 轮转只接受当前目标 checkpoint root 内的历史路径，并在新 checkpoint 所有 rank 成功写入后执行；从其他实验 root 加载的源 checkpoint 是只读输入，不能进入删除候选。

继续旧 checkpoint 时必须保持：

- BACE history prior 和 forgetting 参数；
- topology、variant 和 acquisition；
- invalid action 与 local credit mode；
- tie-break identity mode；
- 其他 collector state signature 字段。

如果要修改这些算法参数，应开始新的 run，而不是复用旧 checkpoint。唯一受控例外是诊断模式 `diagnostic_rmin2_to4`：它只允许 `min_natural_roots: 2→4`，要求独立输出 root，并写出 source/destination、签名差异和 history digest；它不是通用的“忽略签名”开关。
