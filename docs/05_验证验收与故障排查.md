# 验证验收与故障排查

## 1. 分层验证顺序

不要从 clone 直接跳到长训练。推荐门禁为：

| 层级 | 目标 | 最低通过条件 |
|---|---|---|
| L0 | 文件和配置 | 路径、模型 shards、ALFWorld、parquet schema 正确 |
| L1 | Python/CUDA ABI | torch/vLLM/FlashAttention/Ray 可导入，CUDA 可见 |
| L2 | CPU 回归 | BACE + metric 测试全部通过 |
| L3 | dry-run | resolved command 与预期完全一致 |
| L4 | 单步 smoke | global step 1、退出码 0、trace `ok=true` |
| L5 | 两进程恢复 | 新进程达到 step 2，history 连续 |
| L6 | branch 专项 | 至少一个 branch request，selected-worker 指标守恒 |
| L7 | 稳定性 | 多 step 无 OOM、Ray 泄漏、task pinning 或 checkpoint 异常 |
| L8 | 正式训练 | 目标 step、validation、trace 和存储全部验收 |

## 2. L0：文件与资产

运行：

```bash
python deploy/gpu/check_gpu_environment.py \
  --expected-gpus "$GPU_COUNT" \
  --model-path "$MODEL_PATH" \
  --alfworld-data "$ALFWORLD_DATA"
```

并单独检查 parquet 行数、schema 和 checksum。模型如果使用 sharded safetensors，index 中每个 shard 都必须存在且非空。

## 3. L1/L2：环境和单测

```bash
cd verl-agent-src
python -m pip check
pytest -q tests/bace_gigpo tests/trainer/ppo/test_metric_utils.py
```

2026-08-28 本分支参考为 `156 passed`。Ray deprecation、NumPy empty mean 或解释器退出时的 `multiprocess ResourceTracker` warning 可能出现；只有 pytest 退出码为 0 才算通过。

## 4. L3：dry-run 核对清单

检查 `resolved_command.sh`：

- `algorithm.adv_estimator=bace_gigpo`；
- `algorithm.bace.variant=batch_erv_exact`；
- `dynamic_root_generation=staged`；
- `staged_root_batching=packed`；
- `branch_execution_mode=selected_worker`；
- `branch_pool_mode=main_reuse`（新实验推荐）；
- `root_active_executor=true`（新实验推荐）；
- `acquisition=batch_erv_exact`；
- `total_leaf_budget=8`，或明确的小型 smoke override；
- `history_initial_mean=0.10`；
- `history_initial_strength=2.0`；
- `history_forgetting=0.8`；
- `batch_erv_threshold=0.005`；
- 正确的模型、train/val、输出路径和 GPU 数；
- 新实验建议 `tie_break_identity_mode=stable_v1`。

## 5. L4：单步 smoke

最低证据：

```text
training/global_step:1
train process exit code = 0
step_00000001/summary.json: status=complete
trace_validation.json: ok=true
```

检查 artifact 中 roots、leaves 和 trainable occurrences 均可追溯。小 horizon 没有 branch 不算失败，但不能用这种 smoke 证明 branch pipeline 正确。

## 6. L5：checkpoint 恢复

推荐流程：

1. run A 只完成 step 1，并保存 checkpoint；
2. 确认 `latest_checkpointed_iteration.txt` 指向 1；
3. 确认 step 1 目录含 `bace_collector_state.json`；
4. 完全退出 run A；
5. run B 使用相同 run name、checkpoint 目录和算法签名；
6. `trainer.resume_mode=auto`；
7. run B 完成 step 2。

验收：

- actor/optimizer/dataloader/global step 同步恢复；
- step 2 的 `history_before_update` 等于 step 1 保存后的 history；
- 缺少或篡改 BACE state 时恢复应失败；
- checkpoint tracker 只指向完整 step；
- 存储轮转能识别上一进程留下的 checkpoint。

## 7. L6：真实 branch 与 selected-worker

在 artifact 根目录运行：

```bash
python examples/bace_gigpo/validate_selected_worker_metrics.py \
  /path/to/bace_artifacts \
  --output /path/to/selected_worker_validation.json
```

脚本要求至少一个 complete step 实际请求 branch，并检查：

- selected-worker flag；
- execution restore replay 为 0；
- active + avoided = dense-equivalent suffix sequences；
- mechanical replay + origin transition = total environment steps。

如果一直没有 branch，先检查 competence、可用结构 anchor 和 capacity，不要为了“产生 branch”随意降低主实验阈值后继续同一个 checkpoint。

## 8. ALFWorld task rotation

相邻 step 有完整 roots artifact 后运行：

```bash
python examples/bace_gigpo/validate_alfworld_task_rotation.py \
  /path/to/bace_artifacts \
  --first-step 1 \
  --second-step 2 \
  --output /path/to/task_rotation.json
```

同一 task index 在一个 step 内必须使用唯一 natural reset key；相邻 step 的 natural game 应推进。Replay 临时绑定的 game 不应永久改变 natural iterator。

## 9. 常见问题

### 9.1 `cannot import vllm/flash_attn` 或 undefined symbol

原因通常是 PyTorch、CUDA、vLLM 和 FlashAttention ABI 不匹配。不要只重装报错的一个包。记录 driver、`torch.version.cuda` 和完整 pip freeze，按一套兼容矩阵重建环境。

### 9.2 CUDA OOM

先降低执行粒度参数：

```text
ACTOR_MICRO_BATCH: 32 -> 16 -> 8 -> 4 -> 1
LOGPROB_MICRO_BATCH: 同步降低
GPU_MEMORY_UTILIZATION: 适度降低
MAX_NUM_BATCHED_TOKENS / MAX_NUM_SEQS: 降低
```

这些主要影响执行和吞吐。不要未经分析就改变 `GROUP_SIZE`、leaf budget、train batch 或 PPO mini-batch，因为它们可能改变算法和比较口径。

### 9.3 Ray worker 启动失败、线程/PID 用尽

每个 ALFWorld env 是一个 Ray actor。设置：

```bash
export OMP_NUM_THREADS=1
export MKL_NUM_THREADS=1
export OPENBLAS_NUM_THREADS=1
export NUMEXPR_NUM_THREADS=1
export RAYON_NUM_THREADS=1
export MALLOC_ARENA_MAX=2
```

并向 Hydra 显式传入目标设备允许的 CPU 数：

```text
ray_init.num_cpus=<limit>
```

容器或 scheduler 的 PID cgroup 限制也必须足够容纳 Ray actors 和线程。

### 9.4 branch 数超过 Replay worker 数

当前代码应自动按 `replay_capacity` 分块。如果仍看到“请求数超过池容量”，确认运行的是当前 commit，且 collector 走 `_execute_branches` 的 chunking 路径。不要在 Coordinator 中提前截断请求；那会破坏冻结的 Exact plan。

### 9.5 Exact Batch-ERV 在规划阶段卡住

当前主线应使用 `ExactBatchErvEngine.global_allocation` 的 DP。检查 traceback 是否误走 `_global_allocations_cartesian_reference`；后者仅供小问题测试，并有规模保护，不应进入正式运行。

### 9.6 dynamic BACE 恢复报 state missing/mismatch

这通常是正确的 fail-fast：

- checkpoint 未完整复制；
- tracker 指向不完整 step；
- `bace_collector_state.json` 缺失；
- 恢复时改了 history/tie/action/topology 参数；
- 混用了不同 run 的 checkpoint。

不要手工伪造空 state。要么补齐原 checkpoint，要么明确开启新 run。

### 9.7 trace validation 失败

优先看 JSON 的 `errors`，再定位对应 step 的：

- manifest；
- branch requests；
- replay results；
- trainable occurrences；
- posterior snapshots；
- summary。

常见原因包括 branch transition 未验证、失败 branch 进入训练、复制 origin arrays 不一致、R/Q budget 不守恒或 advantage component 不一致。

旧 150-step run 是一个特殊例子：训练本身完成，但 validator 在 JSONL 解析阶段直接抛出 `JSONDecodeError`；当前已确认至少 `step_00000001/leaves.jsonl` 第 1184 行被截断。这类语法损坏发生在语义校验之前，不能通过放宽 validator 阈值解决，也不能把 `summary.json=status=complete` 当成全量 trace 已通过。先只读备份原 artifacts，再统计损坏范围；不要就地删行或拼接内容来“修复”正式证据。

### 9.8 ALFWorld StateID snapshot 找不到

这是当前仓库的已知文档/代码差异，不是安装问题。当前代码没有 StateID snapshot backend。继续使用 prefix/fast replay，或另立任务补齐 snapshot 实现及测试。

### 9.9 从另一个实验 checkpoint 恢复后源 actor 被删除

当前 FSDP manager 已修复该边界：只在新 checkpoint 全部保存成功后轮转，且只轮转当前目标 checkpoint root 内的历史 actor。若仍观察到跨目录删除，立即停止作业并核对 commit；不要用增大 `MAX_CHECKPOINTS` 掩盖不同实验 root 被混入轮转集合的问题。

诊断性 `R_min: 2→4` 恢复还必须同时满足：显式开启 `checkpoint_migration.enabled=true`、mode 为 `diagnostic_rmin2_to4`、目标输出目录与源 checkpoint root 不同，并生成 `checkpoint_migration.json`。其他签名差异继续 fail-fast。

## 10. 正式实验的最低记录

每次可发表或可交接的 run 至少保存：

- Git commit SHA；
- 完整 resolved command；
- working tree patch；
- Python/pip/CUDA/vLLM/driver 版本；
- GPU 拓扑与可见设备；
- 模型、ALFWorld 和 parquet checksum；
- run name 与随机种子；
- 每 step artifacts；
- trace validation；
- checkpoint tracker 和轮转记录；
- stdout/stderr 和资源监控；
- validation 指标。

缺少这些记录时，应把结果标记为 exploratory，而不是正式可复现实验。
