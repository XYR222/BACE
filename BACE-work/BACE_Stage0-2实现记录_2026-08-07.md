## 3. Stage 1：Replay 基础设施

### 3.1 Natural root 事件日志

新增 `recipe/bace_gigpo/types.py` 和 `root_store.py`，把 natural rollout 转换为不可变的 root event log。每个 pre-action occurrence 记录：

- task、root、trajectory 和 occurrence ID；
- step index 与剩余 horizon；
- exact pre-action observation；
- prompt token IDs、response token IDs 和 response loss mask；
- rollout old log-probabilities；
- raw model response；
- parsed/canonical environment action；
- admissible action set；
- post-action observation、reward 和 terminal 标记；
- ALFWorld game file/reset key 和任务描述。

这一结构同时服务于 anchor grouping、replay、prompt identity、copied-origin old-log-prob 复用和最终 lineage。

### 3.2 Structural anchor 与 origin pool

新增 `anchor_index.py`，保持原 GiGPO 的 exact pre-action observation grouping 语义。一个状态只有同时满足以下条件才是 Stage 2 structural anchor：

1. 在同一任务的 natural roots 中重复出现；
2. 至少观察到两个不同的 canonical actions。

每个 anchor 按 action 保存 concrete natural occurrence pool。branch origin 不是抽象的状态或动作，而是从确实执行过目标 action 的自然 occurrence 中选择。

### 3.3 ALFWorld same-game replay

扩展了：

```text
agent_system/environments/env_package/alfworld/envs.py
agent_system/environments/env_manager.py
```

worker replay 流程为：

```text
bind recorded game file
-> reset the same game
-> replay recorded canonical action prefix
-> reject early terminal
-> rebuild observation/admissible-actions/history state
-> return the restored anchor state
```

natural root 环境池与 branch replay 环境池彼此独立且持久存在，避免 replay 改写 natural rollout worker 的状态。

### 3.4 Replay validator

新增 `replay/validator.py` 和 `replay/alfworld.py`。validator 检查：

- replay 是否异常退出；
- prefix 是否提前 terminal；
- restored observation anchor 是否与 expected anchor 完全一致；
- restored admissible action set 是否一致；
- selected action 是否仍然可执行；
- copied origin 的 prompt、response 和 token identity 是否成立。

只有 `replay_ok=true` 的 request 才能生成 branch training data。

## 4. Stage 2：固定拓扑 Branch Rollout

### 4.1 固定 topology coordinator

新增 `coordinator.py`，第一版使用固定：

```text
fixed_root_count = 6
fixed_branch_count = 1
```

流程为：

1. 使用冻结的旧策略生成 6 条 natural roots；
2. 构建 natural structural anchor index；
3. 随机选择一个有效 anchor；
4. 从该 anchor 的自然 observed actions 中随机选择 action；
5. 从该 action 的 natural origin pool 中随机选择 concrete occurrence；
6. 构造带完整 prefix、expected state、copied response 和 lineage 的 `ReplayRequest`。

此阶段的随机选择是为了先验证完整 branch 工程路径；ERV 与动态 topology 属于后续 Stage 4-5。

### 4.2 Copied branch origin

replay 恢复到 selected anchor 后，不重新调用模型生成或强制解码目标 action，而是：

1. 复制 selected concrete natural occurrence 的完整 raw CoT-action response；
2. 在恢复后的环境中重新执行其 canonical action；
3. 断言环境实际执行的 projected action 与 selected action 一致；
4. 从 action 后 observation 开始生成新的 continuation。

copied origin 作为新的 trainable occurrence：

- prompt/response tokens 与 natural origin 相同；
- old log-probabilities 复用 natural origin 的值；
- trajectory/occurrence/leaf lineage 改为当前 branch；
- terminal reward 改为当前 branch leaf 的最终 outcome。

### 4.3 Fresh suffix

新增 `rollout_collector.py`，在 copied origin 之后继续使用同一个冻结策略生成 fresh suffix。suffix：

- 继承 concrete origin 的 remaining horizon；
- 每一步都是真实的新 policy draw；
- 保存新的 prompt、response、old log-prob 和环境 transition；
- 属于同一个 branch leaf；
- 不把 mechanical replay prefix 放入训练 batch。

### 4.4 Leaf 与 occurrence 分离

训练数据只包含三类 occurrence：

```text
natural root occurrence
branch_origin occurrence
branch_suffix occurrence
```

replay prefix 只用于恢复环境，没有新增训练 occurrence，因此不会随 branch 数重复训练 shared prefix。

为每个训练样本增加了：

- `source_type`；
- `leaf_id`；
- `traj_uid`；
- `occurrence_id`；
- `task_batch_index`；
- replay 和环境相关 metadata。

### 4.5 Trainer 接入

修改 `verl/trainer/main_ppo.py` 和 `verl/trainer/ppo/ray_trainer.py`：

- `algorithm.bace.enabled=false` 时继续使用原 `TrajectoryCollector`；
- 启用时创建独立 branch environment pool 和 `BaceTrajectoryCollector`；
- rollout 完成后仍进入 upstream 的 old-log-prob、reference KL、GiGPO advantage 和 PPO actor update；
- 增加 `bace/requested`、`bace/validated`、`bace/skipped` 训练指标。

因此 Stage 2 没有另建一套 optimizer 或 actor loss。

## 5. 实现过程中发现并修复的问题

第一次真实 NPU smoke 已成功完成 replay 和 branch suffix 生成，但在合并 root、branch origin 和 branch suffix 时失败：

```text
ValueError: all the input arrays must have same number of dimensions
```

原因是 NumPy 对等长的嵌套 metadata（例如 admissible action list）会自动构造二维 object array，而 ragged root metadata 是一维 object array。`DataProto.concat` 要求同一字段维度一致。

修复方式是在 concat 前统一 `non_tensor_batch`：

- 第一维始终是 batch 维；
- 每行的嵌套 metadata 作为一个 object 元素保存；
- 再对 root/origin/suffix 缺失字段进行对齐。

新增回归测试覆盖“一维 root metadata + 二维等长 suffix metadata”的合并场景。

## 7. Stage 3：全叶优势与局部 credit

新增 `recipe/bace_gigpo/advantage.py`，并注册 `bace_gigpo` advantage estimator。实现遵循“leaf 是回报统计单位、occurrence 是 PPO 训练单位”的边界：

1. 先按唯一 `(task_id, leaf_id)` 收集自然叶和 branch 叶的终局回报；
2. 在 task 内进行全叶均匀的 global normalization；
3. branch origin 和同一 branch 的 fresh suffix 共享该 branch leaf advantage；
4. natural occurrence 只继承自身 natural leaf advantage，不因被复制为 origin 而重复获得 branch 回报；
5. 对 exact `(task, anchor)` occurrence group 使用总体标准差计算局部 credit；singleton 或常数 group 的局部 credit 为零。

trainer 额外保留 `bace_leaf_advantage` 与 `bace_local_advantage`，用于核对最终合成前的两个分量。

## 8. Stage 4：后验、ERV 与顺序 acquisition

新增 `posterior.py`，实现：

- 带 natural/branch evidence 计数的可变 Beta posterior；
- 以弱 instance competence 为中心的 natural evidence 初始化；
- Monte Carlo Bayes simple regret；
- Beta-Bernoulli 单次观测的 exact ERV；
- 数值稳定的 ERV-softmax action distribution 和 anchor expected utility。

在 `coordinator.py` 中新增 `ExpectedErvCoordinator`。每轮每个 task 最多提出一个 branch request，并严格采用：

```text
选择 frozen anchor/action/origin
-> replay 并生成 branch outcome
-> 强制更新 selected pair posterior
-> 对该 branch fresh suffix 命中的 frozen pair 至多更新一次
-> 重新计算 ERV 后进入下一轮
```

natural roots 建立的 anchor/action/origin support 在整个 round 内冻结；branch 中出现的新状态或新动作不扩展 acquisition support。新增 `bace/erv_rounds` 记录真实顺序 acquisition 轮数。

## 9. Stage 5：动态 topology 与 competence history

新增 `competence.py` 和 `topology.py`，实现：

- 按 task family 保存只由 selected natural roots 更新的滞后成功/失败历史；
- 指数遗忘、受上下界约束的 task-to-instance prior transfer；
- pilot competence posterior；
- 通过 `P(phi > threshold)` 计算 readiness；
- `round((B - pilots) * readiness)` branch quota；
- root-side capacity correction、`L_max` anchor capacity 和 `R + Q = B` 断言。

branch outcome 不进入 competence history。collector 支持：

```yaml
algorithm.bace.topology: fixed | dynamic
algorithm.bace.acquisition: random | erv
```

dynamic topology 保留 candidate-root preallocation 兼容模式：先按 `total_leaf_budget` 在同一冻结策略下生成候选 natural roots，再按 pilot、planned roots、capacity correction 的顺序 reveal。未 reveal 的 roots 被丢弃，不进入 posterior、anchor、advantage、history 或 PPO。

现已新增可选 `dynamic_root_generation=staged`：只生成 pilots，计算 readiness 后按需补充 roots，并对容量不足的 task 逐条执行 root-side correction。原 `preallocated` 逻辑没有删除；`staged` 模式已经通过真实单卡 NPU smoke，达到 `generated roots = final R` 和 `discarded roots = 0`。详细设计和证据见《BACE动态Topology分阶段Root生成设计与实现_2026-08-07.md》。

## 10. Stage 6：Action-aggregated local credit

Stage 6 在全叶优势实现上增加可配置的局部 credit 模式：

```yaml
algorithm.bace.local_credit_mode: occurrence  # occurrence | action_mean
```

`action_mean` 模式先在 exact anchor 的全部 trainable occurrences 上计算总体均值与标准差，再按 `(task, exact anchor, canonical action)` 聚合回报并广播 action-level local advantage。相同 action 的 occurrences 因此共享 local credit，但每条 occurrence 自身的 leaf-global advantage 保持不变。单元测试单独验证了这两个性质。

## 11. Stage 7：WebShop replay 工程链路

WebShop 扩展仍复用同一 BACE 算法层，没有引入第二套 coordinator 或 loss。

### 11.1 Worker 与 vector env

`WebshopWorker` 现在保存 `_last_session_idx`。`replay(session_idx, prefix_actions)` 会固定 reset 到原 session，逐步执行 canonical prefix，并拒绝在 prefix 完成前 terminal；最终返回恢复页面、done、info 和当前 available actions。

`WebshopMultiProcessEnv` 在 reset/step info 中持续携带 `session_idx`，支持不超过 worker pool 的可变 replay batch，并只激活前 N 个 branch workers，因而适配每轮请求数变化的顺序 ERV。

### 11.2 Manager 与 prompt identity

`WebshopEnvironmentManager` 在 reset/step/replay observations 中统一提供格式化的 `admissible_actions`，并在 step info 中记录 `projected_action`。replay 使用请求中的：

- session reset key；
- task description；
- canonical prefix actions；
- prefix pre-action observations。

恢复后重建 `SimpleMemory`、格式化页面 observation、action history 和当前 prompt。通用 `ReplayAdapter` 随后复用与 ALFWorld 相同的 anchor、action-set、selected-action 和 prompt-token identity 验证。

### 11.3 通用接入

natural rollout 现在按环境选择 reset key：ALFWorld 使用 `extra.gamefile`，WebShop 使用 `session_idx`。branch factory 改为环境分发，分别构造独立、持久、每个训练 task 一个 worker 的 ALFWorld 或 WebShop replay pool。数值型 WebShop reset key 在 root store 中归类为 `webshop` task family。

WebShop 回归测试覆盖：

- exact session/action-prefix replay；
- prefix 提前 terminal 拒绝；
- available-action restoration；
- manager memory/prompt reconstruction；
- 两个 worker 的 session 状态隔离。

当前 ALFWorld Conda 环境没有安装 WebShop 所需的旧 `gym` 依赖，也没有启动 WebShop 数据服务，因此本轮未声称完成真实 WebShop/NPU smoke。Stage 7 的结论限定为工程链路和 fake-env 回归通过；首次真实 WebShop 训练前仍需在对应 WebShop 运行环境中验证页面数据版本、服务确定性和 prompt-token identity。

## 14. Stage 9：ALFWorld Invalid Action / Replay Action Identity

依据 Invalid Action 实现规范，natural rollout 现在区分 format-valid 与 environment-valid，并保存未被 projection 改写的完整 CoT/action response。主模式以 `valid::<env command>` 和 `invalid::<raw action body>` 建立严格身份；可解析 invalid/no-op edge 保留在 ERV candidate 中。Replay 对 invalid 不再要求 admissible membership，而是在提交同一 concrete raw response 后检查 action identity、post observation、immediate reward 和 done。
