# BACE 方法参数决策与实现完整性

## 1. 当前实现结论

当前代码已经实现了 BACE 主流程的可运行版本：natural root 采集、anchor/action identity 索引、Beta competence posterior、动态 root/branch budget、ERV acquisition、ALFWorld Replay 校验、branch suffix 采集、advantage 计算、Invalid Action strict identity、old-log-prob 诊断，以及逐 step artifact 保存。

已通过的工程验证包括 BACE 单元测试、Replay validator、artifact validator 和真实 ALFWorld/NPU 单卡训练。需要明确的是，“代码路径已实现”不等于“所有方法决策已由大规模实验确定”。目前仍有参数和实验设计选择需要固定，尤其是 competence gate、budget 分配和 Replay 失败处理。

当前尚未完全实现或尚未定量验证的能力：

- staged 与 preallocated 的成对 wall-clock/token 节省报告；
- Replay、root generation、artifact I/O 的独立计时与占比汇总；
- 周期性 `npu-smi` 利用率/显存采样和 Ray worker 利用率；
- old-log-prob 偏差的修复与基于偏差的训练控制；
- 跨 action/anchor fallback（会改变 strict identity 下的 ERV 采样语义，默认不启用）；
- 多 seed、不同任务族和更长训练下的 BACE 效果结论。

## 4. 重要语义说明

`total_leaf_budget=B` 表示每个 task 最终满足 `R + Q = B`，其中 `R` 是 natural roots，`Q` 是 Replay branches。`pilot_roots` 先消耗 root 预算，剩余预算由 competence readiness 决定是否转换成 branch；capacity correction 会在 anchor 不足时把 branch slot 转回 root slot。

`competence_threshold=0.35` 不是为了绕过 competence 判断，而是避免初始 success=0 时 Beta(1,3) readiness 过低，使完整训练从第一步起永久 `Q=0`。正式论文实验仍应把 0.35 与 0.5 作为预注册的敏感性比较，而当前主脚本固定使用 0.35。

`strict_identity` 下，格式正确但环境不接受的动作仍保留为独立 invalid identity。Replay 只接受同一 anchor/action identity 语义，不能把不同 action 或不同 anchor 自动替换。

## 5. 结果判定标准

一次完整训练至少应满足：退出码为 0；所有保存 step 的 `trace_validation.ok=true`；`R+Q=B`；没有 unknown/failed branch 进入训练 batch；TensorBoard 存在 `perf/throughput`、`timing_s/gen`、`timing_s/update_actor`；并且至少有部分 step 的 `final_branches_mean>0`，否则只能说明 root-only 管线工作，不能说明 Replay BACE 已被训练。
