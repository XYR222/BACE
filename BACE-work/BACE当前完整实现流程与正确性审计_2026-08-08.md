## 1. 阅读结论

当前代码已经实现了 BACE 主版本的完整工程路径：

1. 采集 natural roots，并保存动作前后状态、token、old log-probability 和环境动作身份；
2. 根据 task-family 历史和 pilot roots 构造 competence posterior；
3. 在每个任务固定总 leaf budget `B` 下动态决定 natural root 数 `R` 与 branch 数 `Q`；
4. 使用 staged root generation，只生成最终需要的 roots，并通过 capacity correction 保证 branch 有足够的 natural anchor 支撑；
5. 从 frozen natural support 构造 exact anchor、action identity 和 concrete origin；
6. 使用 Beta-Bernoulli posterior、one-sample ERV、ERV-softmax 顺序选择 anchor/action；
7. 对 ALFWorld 和 WebShop 执行环境级 Replay，严格校验恢复状态、prompt、动作身份和动作后的 transition；
8. 将成功 branch 组装为 `branch_origin + fresh branch_suffix`，机械 replay prefix 不进入训练；
9. 对全部 natural/branch terminal leaves 做统一 leaf credit，对最终所有 trainable occurrences 做 local credit；
10. 将 root、branch origin 和 branch suffix 放入同一个 PPO actor update；
11. 按 step 保存可离线复核的完整 trace，并提供结构验证器。

但“主路径已编码”不等于“方法已经被完整实验证明”。当前有三个重要证据边界：

- 已完成的真实 ALFWorld/NPU 单卡 10-step 训练中，所有 step 的最终 branch 数都是 0，因此该实验没有覆盖真实训练中的 ERV Replay branch；
- 完整 8 卡、150 epoch 的 BACE 主方案训练脚本已经写好，但尚未完成一次端到端训练；
- old-log-probability 的 rollout 值与 trainer 重算值存在可见差异，当前只记录和报告，没有修正或据此阻断训练。

因此，最准确的总体结论是：

> BACE 主版本的算法与工程组件已经接通，单元测试和局部真实环境验证覆盖了 Replay 等关键组件；真实 NPU 训练已经验证 root-only 主干、保存与 checkpoint，但尚未完成包含成功 branch 的中长程/8 卡主方案闭环验证。

## 4. 核心对象和不变量

### 4.1 Budget

对每个 task instance：

```text
B = total_leaf_budget
R = final natural root count
Q = final topology branch-slot quota
R + Q = B
```

这里 `Q` 是 topology 计划的 branch slot 数。若 Replay 最终失败，当前实现不会用跨 action/anchor 的样本补齐，实际成功 branch leaf 数可能小于 `Q`。因此需要分别检查：

- `final_branch_count`：计划的 branch quota；
- `requested`：实际发出的 Replay 请求数；
- `validated` / `successful_branches`：真正进入训练的 branch 数。

不能只看到 `R + Q = B` 就断言最终训练 batch 也有 `B` 条成功 terminal leaves。

### 4.2 Terminal leaf 与 trainable occurrence

两者不是同一个概念：

- natural root 是 terminal leaf，同时包含多个 trainable occurrences；
- 成功 branch 是新的 terminal leaf；
- branch origin 是 copied selected action 的 trainable occurrence；
- branch suffix 中每个 fresh policy action 都是 trainable occurrence；
- mechanical replay prefix 只恢复环境，不是 terminal leaf，也不是 trainable occurrence。

训练来源固定为：

```text
root
branch_origin
branch_suffix
```

### 4.3 冻结与动态更新

branch phase 开始后冻结：

- natural roots；
- structural/effective anchor support；
- 每个 anchor 的 candidate action identity set；
- 每个 `(anchor, action)` 的 concrete natural origins；
- actor 参数，直到整个 rollout batch 完成。

每条成功 branch 后允许变化：

- selected pair 的 Beta posterior；
- fresh suffix 命中 frozen existing pair 时对应的 posterior；
- ERV；
- action sampling probability；
- anchor utility；
- 各 anchor 已使用 branch capacity。

fresh suffix 中出现的新 anchor/action 可以进入最终训练分组，但不能在当前 branch phase 中扩展 acquisition support。

## 5. Trainer 接入与配置约束

入口文件：

- `verl/trainer/config/ppo_trainer.yaml`；
- `verl/trainer/main_ppo.py`；
- `verl/trainer/ppo/ray_trainer.py`。

当：

```yaml
algorithm.adv_estimator: bace_gigpo

```

时，`main_ppo.py` 会：

1. 强制 `actor_rollout_ref.rollout.n == 1`；

    total_leaf_budget: 8

`0.35` 是为避免初期完全 root-only 而给出的实验推荐，不是已经由对照实验确定的最优值。

## 7. Natural root 数据是怎样构造的

`recipe/bace_gigpo/root_store.py` 将环境 collector 的扁平 `DataProto` 按 `traj_uid` 重建为不可变 `RootEventLog`。

每个 root 保存：

- `task_id/task_family/episode_group_id/root_id`；
- `environment_reset_key`；
- task description 和原 batch index；
- terminal reward 与 `won`；
- 按 step 排序的全部 `RootEvent`。

每个 occurrence 保存：

- 动作前 exact observation；
- prompt token IDs；
- response token IDs；
- response loss mask；
- rollout old log-probabilities；
- raw model response；
- parsed environment action；
- admissible action set；
- 动作后 observation、immediate reward、done；
- remaining horizon；
- action identity、format validity、environment validity。

关键正确性要求：

1. prompt/response/token mask 必须只提取 attention mask 中的 active token；
2. 同一个 `traj_uid` 的 step 必须排序；
3. terminal reward 只决定该 root leaf 的 outcome，不可被中间 immediate reward 替代；
4. root event log 在 branch phase 中不可修改。

## 8. Anchor 与 Action Identity

### 8.1 Anchor

`AnchorIndex` 的 grouping key 是：

```text
(task_id, to_hashable(pre_action_observation))
```

这与 GiGPO exact observation grouping 保持一致。当前没有做语义相似度、文本模糊匹配或历史摘要匹配。

结构 anchor 必须同时满足：

- `step_index != 0`；
- 至少有 2 个 natural occurrences；
- 至少有 2 个不同 statistical action identities。

排除 step 0 是因为相同任务的 root 初始状态天然重复，但它不代表自然 rollout 中再次汇合形成的可比较决策点。

### 8.2 strict identity

主方案 `strict_identity` 的规则：

```text
format 无法解析       -> action_identity = None，不进入统计候选
格式正确且环境接受     -> valid::<parsed action>
格式正确但环境拒绝     -> invalid::<parsed action>
```

不做大小写、空白、同义词、对象名或命令模板的语义 canonicalization。这样能够避免把两个环境上不同的 edge 合并成一个统计动作。

### 8.3 Invalid Action Replay

invalid action 是“模型输出可以解析为环境命令，但当前环境不接受”的动作。它通常产生 `Nothing happens.` 等 no-op transition。

对 invalid natural origin：

- Replay 恢复后不要求该 action 出现在 admissible actions；
- 仍执行原始 raw response/parsed action；
- 必须复现相同 `invalid::<action>` identity；
- 必须复现相同 post observation、reward 和 done。

因此，之前出现的 `go to diningtable 1` 不在恢复 action set 中，不一定是拼写错误。若自然 occurrence 本身被记录为 invalid，它可以作为 no-op identity Replay；若自然 occurrence 被记录为 valid，而恢复后 action set 缺少它，则说明恢复状态或动作集合不一致，必须拒绝。

另有两个显式消融模式，但不属于当前主方案：

- `valid_only_branch`：invalid identity 不进入 branch acquisition；
- `single_invalid_bucket`：所有 invalid actions 合并为一个 bucket。

## 9. Competence posterior 与动态 Topology

### 9.1 历史先验

每个 task family 保存衰减 success/failure：

```text
S_t = forgetting * S_(t-1) + current natural successes
F_t = forgetting * F_(t-1) + current natural failures
```

历史只由最终选中的 natural roots 更新，branch outcome 不进入 task-family history。这样避免主动采样 branch 反过来污染自然能力估计。

先计算历史均值，再把转移强度限制到 `[history_min_strength, history_max_strength]`。当前建议：

```text
base Beta = Beta(1, 1)
transfer_fraction = 0.1
strength range = [2, 8]
forgetting = 0.95
```

### 9.2 Pilot posterior 与 readiness

对一个任务的 `pilot_roots` 结果：

```text
posterior alpha = prior alpha + pilot successes
posterior beta  = prior beta  + pilot failures
readiness = P(competence > competence_threshold)
```

初步 branch quota：

```text
planned_Q = round((B - pilot_roots) * readiness)
R = B - planned_Q
```

代码使用 `floor(x + 0.5)` 实现正数 round-half-up，而不是 Python bankers rounding。

### 9.3 Capacity correction

只有满足 ERV threshold 的 exact anchor 才算 effective anchor。最大 branch capacity：

```text
capacity = effective_anchor_count * max_branches_per_anchor
```

如果：

```text
capacity < planned_Q
```

则逐个把 branch slot 转换为 root slot，直到容量足够或 `Q=0`。每次转换仍保持 `R + Q = B`。

该机制的含义是：模型即使 competence 较高，如果 natural roots 没有形成足够的重复状态和动作分歧，也不能凭空 Replay branch。

## 10. Staged Root Generation

旧的 `preallocated` 路径仍被保留为可选模式：先为每个任务生成 `B` 条 candidate roots，再只选前 `R` 条，其余丢弃。

主方案 `staged` 的实际过程：

1. 每个任务先生成 `pilot_roots` 条 roots；
2. 计算 competence readiness 和目标 `R/Q`；
3. 只对尚未达到目标 `R` 的 task 发下一 wave；
4. 达到目标 `R` 后计算 effective anchor capacity；
5. 若容量不足，只对 deficient task 再生成 1 条 root，并执行一次 `Q -> R`；
6. 重复直至 capacity correction 收敛；
7. 断言每个 task 实际生成数等于最终 `R` 且不超过 `B`。

这已经解决了“逻辑上 `R+Q=B`，但前面仍实际生成 B 条 roots 再丢弃”的计算浪费问题，同时没有删除原 preallocated 逻辑。

尚缺的不是 staged 算法本身，而是定量性能报告：当前没有把 root generation、Replay、artifact I/O 单独计时，也没有自动做 staged/preallocated 成对比较。

## 11. ERV Acquisition

### 11.1 Local posterior

对 frozen anchor `z` 的每个 observed action `u`：

```text
alpha(z,u) = local_prior_strength * prior_mean + successes(z,u)
beta(z,u)  = local_prior_strength * (1-prior_mean) + failures(z,u)
```

natural occurrence 的 outcome 使用它所属 natural root 是否成功。

### 11.2 Regret 与 ERV

`PosteriorEngine` 使用 Monte Carlo Beta samples 估计当前 Bayes simple regret：

```text
E[max_u p_u] - max_u E[p_u]
```

每个 action 的 one-sample ERV 根据一次 predictive Bernoulli success/failure 后 posterior mean 的变化，计算 expected next best mean 相对 current best mean 的提升，并截断到非负值。

注意：代码里的 `regret` 使用 MC；当前 one-step `erv_by_action` 使用 posterior mean 的解析式计算，不是为 success/failure 后各自再跑一次 MC regret。审查理论公式时必须以当前代码这一具体定义为准。

### 11.3 动作与 anchor 选择

动作分布：

```text
mu(u|z) = softmax(ERV(z,u) / erv_temperature)
```

anchor utility：

```text
U(z) = sum_u mu(u|z) * ERV(z,u)
```

每轮对每个仍有 quota 的 task：

1. 重算所有未达到容量上限的 anchor；
2. 选择 utility 最大的 anchor；
3. utility/regret/evidence 参与确定性 tie-break；
4. 按 ERV-softmax 随机采样 action；
5. 从该 action 的 natural concrete origins 中均匀采样一个 occurrence；
6. 每个 task 每轮最多提交一个请求，不同 task 的请求可以批量 Replay。

### 11.4 顺序更新

每条验证成功并完成 suffix 的 branch 后：

- selected `(anchor, action)` 必须按 branch terminal success 更新一次；
- suffix 若命中 frozen existing `(anchor, action)`，每个 pair 在该 branch 内最多额外更新一次；
- 新 anchor/action 不扩展 acquisition support；
- 重新计算下一轮 ERV 和 utility。

Replay 失败不作为 Bernoulli failure 更新 posterior，因为那是工程恢复失败，不是 continuation outcome failure。

## 12. Replay 请求、恢复与严格验证

### 12.1 ReplayRequest

ERV 最终选择的是：

```text
task -> anchor -> action identity -> concrete natural origin occurrence
```

请求携带：

- concrete environment reset key；
- anchor 之前的 parsed action prefix；
- prefix 中对应的 observations；
- expected anchor observation/key/action set；
- copied raw response、parsed action、action identity；
- copied response token IDs、loss mask、old log-probs；
- original prompt token IDs；
- expected post-action observation/reward/done；
- remaining horizon。

### 12.2 Replay 前验证

环境 adapter：

1. 绑定同一个 ALFWorld game 或 WebShop session；
2. reset；
3. 机械执行 anchor 前的 action prefix；
4. 重建 environment manager memory/prompt；
5. 校验以下条件。

```text
未提前 done
restored exact anchor key == expected anchor key
natural valid action 在 restored action set 中可执行
可选：restored action set 与 expected action set 集合完全相同
rebuilt prompt active token IDs == original prompt token IDs
```

失败分类包括：

```text
ANCHOR_KEY_MISMATCH
ACTION_SET_MISMATCH
SELECTED_ACTION_NOT_EXECUTABLE
EARLY_TERMINATION
RESET_KEY_MISMATCH
PROMPT_IDENTITY_MISMATCH
ENV_EXCEPTION
```

### 12.3 Copied action 后验证

恢复到 anchor 后，代码执行原 natural occurrence 的 raw response/parsed action，然后校验：

```text
action identity 相同
post-action exact observation 相同
immediate reward 相同
done flag 相同
```

对应失败分类：

```text
ACTION_IDENTITY_MISMATCH
TRANSITION_OBSERVATION_MISMATCH
TRANSITION_REWARD_MISMATCH
TRANSITION_DONE_MISMATCH
```

只有两层验证全部通过，branch 才有资格生成 suffix 和进入训练。

### 12.4 Retry 边界

`max_origin_retries` 只允许：

- 保持同一个 task；
- 保持同一个 frozen anchor；
- 保持同一个 selected action identity；
- 换另一个 natural concrete origin；
- 避免重复使用已失败 origin。

当前不允许跨 action 或跨 anchor fallback。原因是那会把“ERV 选择了 `(z,u)`”悄悄变成另一项实验，导致 posterior update 和实际采样行为不一致。

## 13. Branch 是怎样进入训练 batch 的

对成功 branch：

### 13.1 Mechanical prefix

- 只恢复环境；
- 不复制 tensor row；
- loss mask 为不存在；
- 不进入 anchor local group；
- 不更新 prefix pair posterior。

### 13.2 Branch origin

- 直接复制 natural selected occurrence 的 prompt/response tensor row；
- response token IDs、loss mask、rollout old log-probs 和 action identity 保持原值；
- 将 `source_type` 改为 `branch_origin`；
- 将 `traj_uid/leaf_id/episode reward` 改为 branch lineage 和 branch terminal reward；
- 作为一个额外 continuation evaluation 进入统一 loss。

它不是新的 policy draw，但当前主版本明确把它作为新的 training occurrence。这正是 `BACE优势_Loss与Branch分布更新实现规范.md` 中的主版本，而不是 unique-edge 可选版本。

### 13.3 Fresh branch suffix

- 从 copied action 后的 observation 开始，由 frozen actor 新生成；
- 每个动作是新的真实 policy occurrence；
- 保存生成时 old log-prob；
- `source_type=branch_suffix`；
- 全部属于对应 branch leaf；
- 可以参与最终 local anchor grouping；
- 只能对 frozen acquisition pair 提供 posterior evidence，不能扩展当轮候选 support。

### 13.4 失败 branch

Replay 或 transition validation 失败时：

- 不创建成功 branch leaf；
- 不把 origin/suffix 放入训练 batch；
- 不更新 success/failure posterior；
- 保存失败 category、request 和 restored state 供排查。

## 14. Advantage 与 Unified PPO Loss

### 14.1 Global leaf credit

对同一 task 的所有最终 terminal leaves：

```text
natural root leaves union successful branch leaves
```

先按 `(task_id, leaf_id)` 去重，再对 terminal rewards 标准化：

```text
A_leaf(l) = (reward(l) - mean_task_leaf_reward) / (std + epsilon)
```

同一 leaf 的所有 occurrences 获得完全相同的 `A_leaf`。

### 14.2 Local credit

最终 batch 中按：

```text
(task_id, exact anchor_obs)
```

重新分组。主模式 `occurrence` 对每个 occurrence 的 `step_rewards` 在 anchor 内标准化。

可选 `action_mean` 先对相同 action identity 的 step reward 求均值，使同一 action 的 occurrences 共享 local score。该路径已实现，但不是当前推荐主模式。

### 14.3 最终优势

```text
A_occurrence = A_leaf + step_advantage_w * A_local
A_token = A_occurrence * response_mask
```

函数把同一个 token tensor同时作为 `advantages` 和 `returns` 返回，沿用 critic-free GiGPO 风格。

### 14.4 Loss

trainer 的顺序是：

1. collector 返回合并 batch；
2. 计算 GiGPO step returns；
3. actor worker 重算 `old_log_probs`；
4. 应用 invalid-action penalty；
5. 计算 BACE advantage；
6. 保存训练诊断；
7. root、branch origin、branch suffix 一起执行一次普通 PPO actor update。

没有单独的 root loss、branch loss 或 ERV-weighted loss。ERV 只控制数据采集，不直接作为 PPO sample weight。

## 15. 保存了哪些关键数据

每个训练 step 在独立目录中保存：

```text
bace_trace/
  step_00000001/
    manifest.json
    roots.jsonl
    leaves.jsonl
    anchors.jsonl
    topology.jsonl
    acquisition_rounds.jsonl
    posterior_snapshots.jsonl
    replay_attempts.jsonl
    branches.jsonl
    trainable_occurrences.jsonl
    summary.json
```

同一个 step 重跑不会覆盖原目录，而会生成 `_attempt_XX` 后缀。

### 15.1 各文件用途

| 文件 | 核心内容 | 可排查问题 |
|---|---|---|
| `manifest.json` | schema、step、PID、git commit、BACE 配置 | 实验身份与配置漂移 |
| `roots.jsonl` | 每条 natural root 概要和选中状态 | 生成/选择 root 数是否正确 |
| `leaves.jsonl` | natural events、状态、动作、tokens、old LP | action identity、状态与 token 审计 |
| `anchors.jsonl` | exact anchor、actions、origins | repeated anchor 和 candidate support |
| `topology.jsonl` | posterior/readiness、R/Q、capacity | 动态 topology 是否符合公式 |
| `acquisition_rounds.jsonl` | 候选 ERV、概率、selected anchor/action | ERV 选择是否正确 |
| `posterior_snapshots.jsonl` | 每轮 alpha/beta 与计数 | posterior 是否按 branch 顺序更新 |
| `replay_attempts.jsonl` | request、恢复结果、耗时、失败类别 | Replay 失败根因 |
| `branches.jsonl` | 成功/失败 branch、origin、terminal reward、suffix IDs | branch lineage |
| `trainable_occurrences.jsonl` | source、leaf、advantages、tokens、两套 LP | 最终 loss 样本审计 |
| `summary.json` | counts、metrics、diagnostics、status | step 级快速判定 |

当 `include_token_arrays=true` 时，trace 会保存 token IDs、loss mask、rollout/recomputed old log-probs。这会显著增加存储，但对 copied origin 和 PPO ratio 排查是必要的。

写入策略是逐行 flush；`fsync=false` 时降低 I/O，但机器硬故障仍可能丢失最后少量 OS page cache。正常异常退出时，已 flush 的 JSONL 通常保留。

## 16. Trace Validator 能证明什么

运行方式：

```bash
python3 -m recipe.bace_gigpo.validate_trace \
  /path/to/bace_trace \
  --output /path/to/report.json
```

当前 validator 检查：

- schema version、step、record index 和 count 连续性；
- root ID 和 natural occurrence ID 唯一；
- parsed/valid/invalid identity 规则；
- 每个 task 的 `R + Q = B`；
- branch quota 不超过 anchor capacity；
- topology 只引用已知 roots；
- 成功 branch 有 validated transition；
- failed/unknown branch 不进入训练 batch；
- branch origin lineage 指向 natural occurrence；
- copied response token IDs、loss mask、rollout old LP、action identity 与 origin 相同；
- acquisition posterior support 在各轮保持冻结；
- 同一 leaf 的 leaf advantage 一致；
- old-log-prob 按 source 的差异统计。

但默认 `ok=true` 只表示结构检查通过，不代表：

- 模型训练效果好；
- competence threshold 合适；
- 有成功 branch；
- ERV 的理论定义一定符合预期；
- old-log-prob bias 足够小；
- staged 比 preallocated 更快。

若要把 old-log-prob 作为硬门槛，必须显式传：

```text
--max-recomputed-logprob-diff
--max-recomputed-probability-diff
```

### 18.3 old-log-prob 问题

当前 trainer 会重算 old log-prob 并用于 PPO，artifact 同时保存 rollout 和 recomputed 值。偏差已被观察到，但尚未：

- 找出在 vLLM/NPU、padding、temperature 或 sharding 上的唯一根因；
- 修复两者不一致；
- 设置超阈值跳过 batch 或停止训练；
- 证明该偏差对最终 ratio/gradient 的影响可忽略。

用户当前选择是先不处理偏差，因此它是已知风险，不应从审计文档中隐藏。

### 18.4 性能观测缺口

当前尚无完整的：

- staged root generation 单独耗时；
- preallocated/staged rollout token 对比；
- Replay 恢复与 suffix generation 分项时间；
- ERV CPU Monte Carlo 时间；
- artifact serialization/flush I/O 时间；
- root/branch token fraction 的标准汇总；
- 周期性 NPU memory/utilization；
- Ray worker idle/utilization；
- 自动 staged/preallocated 成对报告。

trainer 自带 `timing_s/gen`、`timing_s/update_actor` 和 throughput 指标，只能提供较粗粒度信息。

### 18.5 可选算法路径

以下不是当前主方案缺失，而是文档中描述但未编码的可选路径：

- Unique-Edge Descendant Backup；
- Full ancestor descendant backup；
- distance-weighted ancestor backup；
- copied origin 只更新 posterior、不进入 loss；
- cross-action/cross-anchor fallback。

如果以后实现，必须以新配置开关加入，不能删除或静默改变当前 copied branch-origin 主逻辑。

### 18.6 理论/实现需要确认的一点

当前 `PosteriorEngine` 的 `regret` 用 Beta MC 估计，但 `ERV` 实际计算的是一次观测后 `max posterior mean` 的期望提升。它与规范中“expected Bayes regret reduction/one-sample EVSI”的关系需要在方法审查时再次确认。代码行为是确定的，但论文公式和命名必须精确匹配这一定义，不能只按名称推断。

## 20. 建议的人工抽查方法

不要只看 `summary.json`。建议随机抽取至少一个有成功 branch 的 step，按以下顺序手工串联：

1. 在 `acquisition_rounds.jsonl` 找 selected anchor/action/request ID；
2. 在 `anchors.jsonl` 确认该 action 和 origin 属于 frozen support；
3. 在 `leaves.jsonl` 找 natural origin，记录 raw response、identity、prompt/response tokens、post-state；
4. 在 `replay_attempts.jsonl` 检查 restored anchor、action set、prompt validation 和 transition validation；
5. 在 `branches.jsonl` 找 branch terminal reward 和 suffix occurrence IDs；
6. 在 `posterior_snapshots.jsonl` 比较 branch 前后 selected pair 的 alpha/beta 是否只增加一次；
7. 在 `trainable_occurrences.jsonl` 确认 branch origin copied tensors 完全相同，但 leaf ID/reward 指向 branch；
8. 检查 mechanical prefix action 没有额外训练 row；
9. 检查 suffix IDs 全部存在并属于同一 branch leaf；
10. 检查同 leaf 的 `leaf_advantage` 完全一致；
11. 检查 source-specific rollout/recomputed LP difference；
12. 再用 validator 复核结构结果。

这条链能够同时检查“ERV 选了什么、Replay 是否真的恢复、训练到底用了什么”，比只观察最终 reward 更适合实现审计。
