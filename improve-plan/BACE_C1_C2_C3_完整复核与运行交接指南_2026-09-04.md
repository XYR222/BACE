## 3. 先理解四类对象

### 3.1 natural root occurrence

root rollout 中真实执行的一条环境 action。每条 occurrence 有唯一 `occurrence_id`，并记录：

- `traj_uid`：所属自然 root；
- `step_index`：在自然 root 中的位置；
- `tree_parent_root_id`：所属根；
- `leaf_id=root:<root_id>`；
- `source_type=root`。

### 3.2 branch origin occurrence

为了从某个 anchor 分支，系统先 replay 自然 root 的前缀，再在同一 state 执行被选中的同一 action。这个复制出来的 origin row 用于携带 branch continuation 的结果证据：

- `source_type=branch_origin`；
- `traj_uid`/`leaf_id` 改为 branch ID；
- `tree_origin_occurrence_id` 指向被复制的 natural occurrence；
- `tree_parent_root_id` 仍指向原自然 root。

它和 natural origin 是同一条逻辑 edge 的两个物理 row，不能同时进入 PPO，否则会重复训练同一个 state-action。

### 3.3 branch suffix occurrence

origin 之后由 branch 新产生的 action。它们是新的逻辑 edge：

- `source_type=branch_suffix`；
- 使用 branch 的 `traj_uid/leaf_id`；
- 始终保留在 PPO 支持集中；
- 当前版本不继续产生 branch-of-branch。

### 3.4 adjustment / PPO padding

三种 padding/副本必须区分：

- `_adjust_batch_padding`：在 reward、old-logprob 和冻结 C0 macro 之前，为批大小整除而复制的物理行；它参与 C0 frozen normalizer，但不代表新 edge，随后从 C1/C2/C3 PPO 支持集移除。
- `copy_trainable`：当前默认。树信用过滤后，从真实 unique edges 随机复制到 `world_size×actor_micro_batch` 的倍数；副本保留完整 loss，参与 PPO，但通过 `bace_ppo_is_padding_copy` 等字段标明不是新逻辑 edge。
- `ppo_padding`：仅在显式选择 `zero_loss` 模式时产生。其 loss mask 为零，只用于形状对齐。

## 4. lineage 如何建立

入口位于：

- `recipe/bace_gigpo/rollout_collector.py`
  - `_set_lineage(...)`
  - `_annotate_tree_lineage(...)`
- `recipe/bace_gigpo/advantage.py`
  - `build_tree_credit_index(...)`

流程如下：

```text
natural roots rollout
        │
        ├─ 每条真实 action 生成唯一 occurrence_id
        │
Exact Batch-ERV 选择具体 anchor occurrence
        │
strict replay 恢复前缀并验证 action/state 身份
        │
        ├─ branch_origin 指回 exact natural occurrence
        └─ branch_suffix 形成新的 branch leaf
        │
merge root/origin/suffix physical rows
        │
build_tree_credit_index 按 occurrence/root/step 建 Direct 与 Descendant
```

关键安全条件：

- ancestry 不使用 `anchor_obs` 文本推断；同文本重复出现不会混淆祖先关系；
- branch origin 必须能找到唯一 natural origin；
- branch 的 parent root、origin step、occurrence 必须一致；
- Exact 模式中，已冻结计划的 branch 如果没有真正执行成功，会直接报错，而不是减少分支后继续训练；
- branch suffix 不被误认为自然 root 的前缀。

## 5. C0、C1、C2、C3 分别做什么

令：

- `e`：当前要训练的唯一 edge；
- `o`：某条 branch 的 natural origin；
- `b`：该 branch 的复制 origin；
- `G(x)`：production pipeline 计算出的 step discounted return，已包含 edge-local invalid penalty；
- `M(x)`：在完整 C0 physical batch 上冻结得到的 occurrence-level macro；
- `γ=0.95`；
- `t_x`：edge 的 env step；
- `Local(·)`：按 task/anchor/action occurrence 口径重新计算的 GiGPO local advantage；
- `w=1.0`：local advantage 权重。

### 5.1 C0：当前 BACE/GiGPO 口径

```text
A_C0(e) = M(e) + w × Local(G(e))
```

C0 是冻结参考口径。树信用变体先在完整 physical batch 上计算它，再开始去重和回传。

### 5.2 C1：只做直接分支的 local backup

对恰好在 `e` 上产生的 direct branches：

```text
candidate_G(e, b) = G(e) + G(b) - G(o)
G_C1(e) = mean({G(e)} ∪ direct candidates)
A_C1(e) = M(e) + w × Local(G_C1(e))
```

direct 情况下 `e=o`，所以 candidate 化简为 `G(b)`。直观上：该 action 的 local credit 同时参考自然 continuation 和从同一 action 出发的 branch continuation。

C1 不把 branch 结果传播到更早的祖先 edge，macro 也保持 C0 冻结值。

### 5.3 C2：C1 local + descendant macro backup

一条在 `t_b` 分出的 branch，会影响同一自然 root 上满足 `t_e≤t_b` 的祖先 edge。每个后代候选为：

```text
candidate_M(e, b) = M(e) + M(b) - M(o)
M_C2(e) = mean({M(e)} ∪ descendant candidates)
A_C2(e) = M_C2(e) + w × Local(G_C1(e))
```

C2 的 local 与 C1 完全相同，只把 branch continuation 的 macro 增量传给前缀祖先。

### 5.4 C3：C2 macro + descendant local-return backup

C3 的 macro 与 C2 完全相同；local return 也向祖先传播，但按 env-step 距离折扣：

```text
candidate_G(e, b)
  = G(e) + γ^(t_b-t_e) × [G(b)-G(o)]

G_C3(e) = mean({G(e)} ∪ descendant candidates)
A_C3(e) = M_C2(e) + w × Local(G_C3(e))
```

它只传播“branch continuation 相对 natural continuation 的增量”，不会把 origin 本身的局部 invalid penalty重复传播给祖先。

### 5.5 三个变体的差异表

| 模式 | 配置值 | Direct local | Descendant macro | Descendant local | PPO 是否保留复制 origin |
|---|---|---:|---:|---:|---:|
| C1 | `o1_local` | 是 | 否 | 否 | 否 |
| C2 | `o1_tree_macro` | 是 | 是 | 否 | 否 |
| C3 | `o1_full_tree` | 是 | 是 | 是，含 `γ` 折扣 | 否 |

三者都保留 natural root edge 和 branch suffix edge。

## 6. 为什么 invalid penalty 的当前处理是正确的

自然 origin 与复制 branch origin 在 strict replay 下执行同一 state 的同一 action，所以二者的 invalid 状态相同。设这条 origin action 的局部 penalty 为 `p_o`：

```text
G(b) = continuation_branch - p_o
G(o) = continuation_natural - p_o
G(b)-G(o) = continuation_branch-continuation_natural
```

origin penalty 在差分中抵消。对更早的 target edge `e`：

```text
G(e) + γ^d × [G(b)-G(o)]
```

保留 `e` 自己的 penalty 一次，只传播 continuation 差异。这正是“先聚合 continuation，再只惩罚当前训练 edge”的实现。

当 `e=o` 时：

```text
G(e)+G(b)-G(o)=G(b)
```

仍然只包含 origin action 自身的一次 penalty，不会出现一个 valid、一个 invalid 的人为不一致。

macro 采用同样的增量形式：

```text
M(e)+M(b)-M(o)
```

因为同一 task 内使用同一个冻结 affine normalizer，这等价于把 continuation 的宏观结果替换到 target occurrence，同时保留 target edge 的局部项。

## 7. PPO 支持集与不变部分

树信用计算前，old logprob、ref logprob、reward 和冻结 C0 macro 都在完整 physical batch 上产生。随后：

```text
keep = 非 branch_origin 且非 _adjust_batch_padding
```

`DataProto.select_idxs(keep_indices)` 会同步过滤 tensor 与 non-tensor 字段，因此不会出现 advantage 已去重但 token/logprob 仍重复的错位。

以下 BACE 语义没有因 C1/C2/C3 改变：

- Exact Batch-ERV 全局分配；
- `R+Q=8`；
- packed root rollout；
- selected-worker branch 执行和 replay；
- capacity correction；
- posterior、family history 和 competence 更新；
- branch outcome 不进入 family history；
- controller 使用 physical rollout evidence，而 learner 使用去重后的 unique-edge PPO support；
- checkpoint/resume 的 BACE history 状态。

换言之，C1/C2/C3 是 learner-side credit assignment 变体，不是新的 branch 调度器。

## 9. PPO 对齐问题及本轮修复

### 9.1 问题

修复前，`compute_advantage(...)` 删除 copied origins 和 adjustment padding 后仅执行：

```text
padding divisor = bace_ppo_world_size
```

正式 2 卡配置是：

```text
world_size = 2
actor.ppo_micro_batch_size_per_gpu = 32
```

因此全局 unique-edge batch 应补到：

```text
2 × 32 = 64 的倍数
```

只补到偶数并不足够。例如过滤后有 198 行，旧实现不再 padding；分到两卡后每卡 99 行，actor 会切成 `32+32+32+3`。最后 3 行被当作一个 micro-batch，而 loss 仍使用按 32-row micro-batch 设置的固定 gradient accumulation。

### 9.2 影响

- 不影响 C1/C2/C3 的 advantage 数值和 lineage 正确性；
- 不会必然报错，因此较隐蔽；
- 会让最后一个不足 32 行的 micro-batch 在 token/sample 聚合中的权重与完整 micro-batch 不一致；
- 破坏 C0/C1/C2/C3“只改变信用逻辑”的严格可比性；
- 当前 1 卡 smoke 把 actor micro-batch 设为 1，无法发现此问题。

### 9.3 已实现行为

本轮只改 learner padding，不改树信用和 rollout：

1. actor micro-batch size 已传入 tree-credit `compute_advantage`；
2. 静态 batch divisor 改为：

   ```text
   world_size × actor.ppo_micro_batch_size_per_gpu
   ```

3. 默认 `tree_ppo_padding_mode=copy_trainable`：随机复制真实 unique edge，完整复制 token、old/ref logprob、advantage、return 和 loss mask；
4. 记录 `bace_ppo_is_padding_copy`、`bace_ppo_copy_of_edge_id` 和 `bace_ppo_copy_source_row`；
5. artifact 将唯一 edge 写入 `trainable_occurrences.jsonl`，将训练副本单独写入 `ppo_training_copies.jsonl`；
6. 保留 `zero_loss` 作为显式 ablation，不删除旧逻辑；
7. 新增 `198→256` 测试，验证每卡 `128=4×32`，并验证复制行保留完整 loss。

该 CPU 集成路径已经通过；正式放行前剩余的是 2×H100 运行门禁，而不是代码中已知的 batch divisor 缺陷。

## 10. 非阻断但应知晓的审计边界

### 10.1 gradient mass proxy 名称偏强

当前 `tree_credit_gradient_mass_proxy_ratio` 的分母，是 C0 advantage 在 **keep_indices 后的 unique support** 上的质量，不包含 physical C0 的 copied origins。它适合比较“同一 unique support 上 Ck/C0 的 advantage mass”，但不是完整的“Ck 对 physical C0 的梯度质量比”。核心训练不受影响，后续应改名或修正分母。

### 10.2 copied origin 的 post-hoc token 审计不足

复制 origin 在保存 trainable diagnostics 前已被删除，所以 smoke 报告中的：

```text
copied_branch_origins_audited = 0
```

并不表示没有 origin，而是 trace 中没有保留其 token/old-logprob 供离线逐 token 对照。`tree_credit_branches.jsonl` 仍保存 branch ID、origin occurrence、root、step、leaf、branch G 和 terminal reward。

运行时通过“从 natural row 选择并构造 origin + strict replay transition 校验”保证一致性；但若要更强的可审计性，应在过滤前另存 origin action token、validity 和 old-logprob 摘要。

### 10.3 三种 smoke 不是同一棵在线树

smoke 脚本顺序启动三个独立进程。即便 seed 相同，环境/模型服务的运行状态也可能令 branch suffix 长度不同，所以三个 smoke 的 trainable occurrence 数不必相等。

“C1 local = C2 local”“C2 macro = C3 macro”等同一 physical batch 不变量，由构造型单元测试验证；在线 smoke 验证的是每个 mode 能独立完成 rollout、replay、credit、PPO 与 trace。

### 10.4 `raw_rewards` 当前是兼容输入

delta 公式使用 `step_rewards` 和 frozen macro 后，`raw_rewards` 仍参与输入完整性校验和 artifact 语义，但不直接进入 C1/C2/C3 的回传公式。这是当前设计结果，不是遗漏。
