# BACE C0 调度优化版：2×H100 三个 seed 的脚本与参数说明

本文说明 ALFWorld / Qwen2.5-1.5B-Instruct 的原始 BACE **C0** 方法，采用已验证的 P1-S 调度优化和 2×H100。C0.5、C1/C2/C3、C4、C7、C8 不适用本说明，必须采用各自 credit mode 与独立输出目录。

## 实际使用的训练入口

三个历史 C0 run 使用的自包含入口：

```text
/hpcwork/xsz96350/fu_project/work-BACE/verl-agent-src/examples/bace_gigpo/
run_alfworld_h100_2gpu_reference_aligned.sbatch
```

该入口不会调用 1 卡/4 卡 wrapper 或 C8 提交器；它加载 CUDA 12.8、激活现有 `verl-agent`，离线使用 Qwen2.5-1.5B-Instruct、ALFWorld cache 和 parquet。默认资源为 1 节点、2×H100、32 CPU、244 GiB、`c23g/rwth2082/23:30:00`。`sbatch --partition`、`--account`、`--time` 能覆盖资源指令，但不改变算法。

## C0 和调度优化的区别

| 维度 | 使用的值 | 含义 |
|---|---|---|
| credit 方法 | `current`（C0） | 保留原始 physical occurrence/origin multiplicity 与当前 GiGPO macro + local advantage；没有树信用替换。 |
| branch worker 调度 | `main_reuse` | branch 复用主 rollout worker 池。 |
| root 调度 | `root_active_executor=true` | 对失活 root 行作 compaction，避免无效 dense rollout。 |

调度优化只改变 rollout/replay 执行和压缩，不改变 Exact Batch-ERV 全局分配、packed root、selected-worker branch 执行、PPO physical-row 语义或 GiGPO-compatible advantage。

必须设置：

```text
BACE_SCHEDULING_PROFILE=optimized
```

它解析为 `branch_pool_mode=main_reuse` 与 `root_active_executor=true`。省略时入口默认 `legacy`（`dedicated + false`），不是三 seed 历史版本。

## C0 基准配置

| 参数 | 值 |
|---|---:|
| estimator | `bace_gigpo` |
| BACE variant / acquisition | `batch_erv_exact` |
| topology / root / batching | `dynamic` / `staged` / `packed` |
| branch execution | `selected_worker` |
| total leaf budget / min natural roots / max branches | 8 / 2 / 2 |
| capacity correction batch size | 4 |
| competence threshold | 0.5 |
| history prior | mean 0.10, strength 2.0，即 Beta(0.2, 1.8) |
| history forgetting / transfer | 0.8 / 0.1 |
| local prior strength | 2.0 |
| Exact Batch-ERV threshold | 0.005 |
| invalid action | `strict_identity`，coefficient 0.1 |
| local credit | `occurrence` |
| PPO alignment policy in the current entry | `copy_trainable`（2026-08 三次 C0 的 resolved command 未记录该后续显式字段，不能把它表述为该字段的历史审计证据） |
| train / val batch | 16 / 128 |
| group size; horizon / response | 8; 50 / 512 |
| LR; PPO mini-batch; per-GPU micro-batch | `1e-6`; 256; 32 |
| TP; rollout/logprob micro-batch | 2; 32 / 32 |
| vLLM max tokens / sequences | 8192 / 1024 |
| KL / gamma | 0.01 / 0.95 |
| step-level advantage weight | 1.0 |
| validation frequency / total steps | 5 / 150 |

运行时会取消 `VLLM_ATTENTION_BACKEND`，以便 H100/vLLM 自动选择可用 FlashAttention；这只是兼容性设置。

## C0 credit mode 的正确写法

历史 C0 命令没有显式 `algorithm.bace.credit_mode`。收集器会把缺省或 `null` 回退为 `tree_credit_mode=current`，因此历史运行实际是 C0/current。

新的 C0 作业建议显式锁定：

```text
BACE_CREDIT_MODE=current
TREE_CREDIT_MODE=current
MACRO_NORMALIZATION_MODE=stable_occurrence
```

这和历史 C0 语义等价。不要设为 C0.5、C4、C7、C8 或任一 C1/C2/C3 tree-credit mode，否则不再是 C0 对照。

## 修改 seed：正式提交模板

`BACE_SEED` 会写为 `env.seed`。不同 seed 必须用不同 `BACE_RUN_NAME`，否则 checkpoint、artifact、TensorBoard、history state 与恢复 tracker 会相互污染。

提交新的 C0 seed 1：

```bash
cd /hpcwork/xsz96350/fu_project/work-BACE/verl-agent-src

sbatch --parsable \
  --partition=c23g --account=rwth2089 --time=15:00:00 \
  --job-name=bace_c0_opt_s1 \
  --export=ALL,\
BACE_SCHEDULING_PROFILE=optimized,\
BACE_CREDIT_MODE=current,\
TREE_CREDIT_MODE=current,\
MACRO_NORMALIZATION_MODE=stable_occurrence,\
BACE_SEED=1,\
BACE_RUN_NAME=bace_alfworld_qwen2_5_1_5b_exact_2gpu_c0_opt_seed1_YYYYMMDD,\
CAPACITY_CORRECTION_BATCH_SIZE=4,\
TARGET_STEP=150,\
SAVE_FREQ=5,\
MAX_CHECKPOINTS=2,\
MILESTONE_CHECKPOINT_STEPS=none \
  examples/bace_gigpo/run_alfworld_h100_2gpu_reference_aligned.sbatch
```

seed 2 时，同时将 `BACE_SEED=2`、job name 中的 `s1`、run name 中的 `seed1` 改为 `2`。只有恢复同一实验时复用旧 run name；新 seed 或新超参数必须创建新 run name。

## 修改 C0 参数

以下启动器变量可以直接写在 `--export`：

| 变量 | 示例 | 用途 |
|---|---|---|
| `BACE_SEED` | `BACE_SEED=2` | 环境 seed。 |
| `BACE_RUN_NAME` | `...seed2...` | 输出与自动恢复身份。 |
| `BACE_SCHEDULING_PROFILE` | `optimized` | 必须保留以使用调度优化。 |
| `BACE_CREDIT_MODE` | `current` | 显式锁定 C0。 |
| `TREE_CREDIT_MODE` | `current` | C0 回退语义。 |
| `CAPACITY_CORRECTION_BATCH_SIZE` | `4` | root correction 粒度。 |
| `TARGET_STEP`, `SAVE_FREQ`, `MAX_CHECKPOINTS` | `150`, `5`, `2` | 训练目标与 checkpoint 轮转。 |
| `MILESTONE_CHECKPOINT_STEPS` | `none` | 禁止额外永久 checkpoint。 |

以下参数目前在入口中以固定 Hydra override 写入，**不能**仅用 `--export` 改。脚本会将脚本路径之后的参数追加到 Hydra 命令末尾，所以须使用末尾同名 key 覆盖：

```bash
  examples/bace_gigpo/run_alfworld_h100_2gpu_reference_aligned.sbatch \
  algorithm.bace.competence_threshold=0.60 \
  algorithm.gigpo.step_advantage_w=0.75 \
  algorithm.bace.batch_erv_threshold=0.010
```

| Hydra 参数 | C0 基准值 | 含义 |
|---|---:|---|
| `algorithm.bace.competence_threshold` | 0.5 | family posterior competence 的 branch/refinement readiness 阈值，不是先验均值。 |
| `algorithm.gigpo.step_advantage_w` | 1.0 | 最终 GiGPO advantage 中步骤级 local advantage 系数，不是学习率。 |
| `algorithm.bace.batch_erv_threshold` | 0.005 | Exact Batch-ERV 设计/容量判断的最小有效 ERV 阈值，不是 success rate。 |

## dry-run、续跑与 checkpoint

提交前可在已有 2×H100 allocation 的计算节点运行 dry-run；它只写 metadata 和解析命令：

```bash
cd /hpcwork/xsz96350/fu_project/work-BACE/verl-agent-src

DRY_RUN=1 BACE_SCHEDULING_PROFILE=optimized BACE_CREDIT_MODE=current \
TREE_CREDIT_MODE=current BACE_RUN_NAME=dry_c0_opt_s1 BACE_SEED=1 TARGET_STEP=1 \
bash examples/bace_gigpo/run_alfworld_h100_2gpu_reference_aligned.sbatch \
  algorithm.bace.competence_threshold=0.60 \
  algorithm.gigpo.step_advantage_w=0.75 \
  algorithm.bace.batch_erv_threshold=0.010
```

检查 `run_metadata/<run-name>/.../resolved_command.sh`，应包含：

```text
algorithm.bace.credit_mode=current
algorithm.bace.branch_pool_mode=main_reuse
algorithm.bace.root_active_executor=true
algorithm.bace.competence_threshold=<目标值>
algorithm.gigpo.step_advantage_w=<目标值>
algorithm.bace.batch_erv_threshold=<目标值>
env.seed=<目标 seed>
```

- `SAVE_FREQ=5, MAX_CHECKPOINTS=2`：每 5 step 保存，保留最近两份。
- 同一 run 被墙钟或节点故障打断后，保持相同 run name、seed、C0 mode、profile 和参数重新提交，脚本自动从最近完整 checkpoint 恢复。
- 历史 seed 0 保存 10、75、100、140；seed 1/2 使用 `MILESTONE_CHECKPOINT_STEPS=none` 以控制存储。若要长期保存点，先在 shell 中 `export MILESTONE_CHECKPOINT_STEPS=10,75,100,140`，不要把逗号列表直接放进 `--export`。
