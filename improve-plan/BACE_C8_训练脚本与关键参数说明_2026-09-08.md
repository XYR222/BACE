# C8 训练脚本、参数与 seed 修改说明

**适用对象：** ALFWorld / Qwen2.5-1.5B-Instruct 的 2×H100 C8 实验。本文记录的是已经实际用于 C8 seed 0 正式 run 的入口与有效参数，不是一个新的实验设计。

## 1. C8 用什么脚本启动

正式 C8 的唯一训练入口是：

```text
/hpcwork/xsz96350/fu_project/work-BACE/verl-agent-src/
  examples/bace_gigpo/run_alfworld_h100_2gpu_reference_aligned.sbatch
```

该脚本是自包含的 2 卡启动器，不会再调用 1 卡或 4 卡脚本。它申请 1 个节点、2×H100、32 CPU、244 GiB RAM；默认 Slurm 指令是 `c23g/rwth2082/23:30:00`。提交时的 `sbatch --partition`、`--account`、`--time` 会覆盖脚本中的同名 `#SBATCH` 指令。

此前一次实际 C8 正式训练由下面的批量提交器发起：

```text
examples/bace_gigpo/submit_tree_credit_c05_c4_c7_c8_2gpu_seed0.sh
```

它会一次提交 C0.5、C4、C7、C8 四个独立作业，因此**不适合只重跑 C8**。该批量脚本给 C8 传入：

```text
BACE_CREDIT_MODE=c8_macro_local_strict_ancestor
TREE_CREDIT_MODE=current
MACRO_NORMALIZATION_MODE=stable_occurrence
BACE_RUN_NAME=bace_alfworld_qwen2_5_1_5b_exact_2gpu_c8_seed0_20260906
BACE_SEED=0
BACE_SCHEDULING_PROFILE=optimized
CAPACITY_CORRECTION_BATCH_SIZE=4
TARGET_STEP=150
SAVE_FREQ=5
MAX_CHECKPOINTS=2
MILESTONE_CHECKPOINT_STEPS=none
```

实际 C8 run 的 metadata 在：

```text
/hpcwork/rwth2089/xsz96350/work-BACE/experiments/alfworld-qwen2.5-1.5b-exact/
  run_metadata/bace_alfworld_qwen2_5_1_5b_exact_2gpu_c8_seed0_20260906/
  3741234_2gpu_optimized_to_step_150/
```

其中 `resolved_command.sh` 是这次运行最终解析出的完整 Hydra 命令，应作为审计依据。

## 2. C8 的方法与固定训练配置

C8 的方法选择由下列三项共同确定：

| 项目 | 实际值 | 作用 |
|---|---:|---|
| `algorithm.bace.credit_mode` | `c8_macro_local_strict_ancestor` | 选择 C8：保留 C0 origin multiplicity，在 C4 macro strict-ancestor backup 基础上加入 local strict-ancestor incremental backup。 |
| `algorithm.bace.tree_credit_mode` | `current` | 不启用旧 C1/C2/C3 的 tree-credit 路径；C8 的实现由 `credit_mode` 分派。 |
| `algorithm.bace.macro_normalization_mode` | `stable_occurrence` | 使用 occurrence 口径的稳定 macro normalization。 |

其余当前有效的 BACE 拓扑/调度口径：

| 项目 | 当前值 |
|---|---:|
| Exact acquisition | `batch_erv_exact` |
| topology / root generation / batching | `dynamic` / `staged` / `packed` |
| leaf budget | 8 |
| minimum natural roots | 2 |
| maximum branches per anchor | 2 |
| branch worker execution | `selected_worker` |
| branch pool | `main_reuse` |
| active-root executor | `true` |
| capacity correction batch size | 4 |
| invalid action | `strict_identity`，penalty coefficient 0.1 |
| local credit | `occurrence` |
| PPO padding | `copy_trainable` |

非 BACE 的训练参数与 AFH 的 GiGPO ALFWorld 基准对齐：Qwen2.5-1.5B-Instruct、train/val batch `16/128`、response length 512、horizon 50、学习率 `1e-6`、PPO mini-batch 256、每卡 PPO micro-batch 32、TP=2、rollout/logprob micro-batch 32、KL=0.01、gamma=0.95、每 5 step validation。

## 3. 三个容易混淆的关键参数

下面三个数是当前 C8 seed 0 的真实值，且它们含义不同。

| 参数 | 当前值 | 它控制什么 | 不是什么 |
|---|---:|---|---|
| `algorithm.bace.competence_threshold` | **0.5** | family 的 posterior competence 达到该阈值后，才具备采用 refinement/branch 拓扑的 readiness 条件。 | 不是 Beta prior 的均值，也不是 ERV 阈值。 |
| `algorithm.gigpo.step_advantage_w` | **1.0** | 最终 GiGPO advantage 中步骤级 local advantage 的系数。值为 1 表示完整保留该项。 | 不是 PPO 学习率，也不是 macro credit 的缩放。 |
| `algorithm.bace.batch_erv_threshold` | **0.005** | Exact Batch-ERV 设计/容量判断中的最小有效 ERV 阈值。 | 不是 competence threshold，也不等于 success rate。 |

相关但未要求修改的 history 先验为：

```text
history_initial_mean=0.10
history_initial_strength=2.0     # 等价于 Beta(0.2, 1.8)
history_forgetting=0.8
local_prior_strength=2.0
```

## 4. 修改 seed：推荐做法

seed 由环境变量 `BACE_SEED` 传入，并写成 `env.seed`。每个 seed 必须使用**不同的 run name**，否则会复用同一输出目录的 checkpoint、artifact、TensorBoard 和恢复 tracker，造成实验污染。

例如提交 C8 seed 1：

```bash
cd /hpcwork/xsz96350/fu_project/work-BACE/verl-agent-src

sbatch \
  --partition=c23g --account=rwth2089 --time=15:00:00 \
  --job-name=bace_c8_s1 \
  --export=ALL,\
BACE_CREDIT_MODE=c8_macro_local_strict_ancestor,\
TREE_CREDIT_MODE=current,\
MACRO_NORMALIZATION_MODE=stable_occurrence,\
BACE_RUN_NAME=bace_alfworld_qwen2_5_1_5b_exact_2gpu_c8_seed1_YYYYMMDD,\
BACE_SEED=1,\
BACE_SCHEDULING_PROFILE=optimized,\
CAPACITY_CORRECTION_BATCH_SIZE=4,\
TARGET_STEP=150,\
SAVE_FREQ=5,\
MAX_CHECKPOINTS=2,\
MILESTONE_CHECKPOINT_STEPS=none \
  examples/bace_gigpo/run_alfworld_h100_2gpu_reference_aligned.sbatch
```

seed 2 只需同时把 `BACE_SEED=2`、作业名中的 `s1` 和 `BACE_RUN_NAME` 中的 `seed1` 改成 `2`。不要只改 run name 而忘记 seed，也不要只改 seed 而复用旧 run name。

## 5. 修改 competence、步骤级优势权重和 ERV threshold

### 当前实现的覆盖机制

上述三个 Hydra 参数目前在训练脚本中写为固定默认覆盖：

```text
algorithm.bace.competence_threshold=0.5
algorithm.gigpo.step_advantage_w=1.0
algorithm.bace.batch_erv_threshold=0.005
```

但脚本最后会把 `sbatch` 中脚本路径之后的所有位置参数追加到 Hydra 命令**末尾**。Hydra 对同一 key 采用最后一个覆盖值，因此可在不编辑脚本的情况下进行一次性实验覆盖。

重要：`BACE_COMPETENCE_THRESHOLD`、`STEP_ADVANTAGE_W`、`BATCH_ERV_THRESHOLD` 目前不是脚本读取的环境变量。把它们放进 `--export` **不会改变训练参数**；必须用下面所示的末尾 Hydra 参数，或先修改脚本。

### 三项同时修改的示例

以下示例使用 seed 1，并把 competence 改为 0.60、步骤级优势权重改为 0.75、ERV threshold 改为 0.010：

```bash
cd /hpcwork/xsz96350/fu_project/work-BACE/verl-agent-src

sbatch \
  --partition=c23g --account=rwth2089 --time=15:00:00 \
  --job-name=bace_c8_s1_comp60_w075_tau010 \
  --export=ALL,\
BACE_CREDIT_MODE=c8_macro_local_strict_ancestor,\
TREE_CREDIT_MODE=current,\
MACRO_NORMALIZATION_MODE=stable_occurrence,\
BACE_RUN_NAME=bace_alfworld_qwen2_5_1_5b_exact_2gpu_c8_s1_comp60_w075_tau010_YYYYMMDD,\
BACE_SEED=1,\
BACE_SCHEDULING_PROFILE=optimized,\
CAPACITY_CORRECTION_BATCH_SIZE=4,\
TARGET_STEP=150,\
SAVE_FREQ=5,\
MAX_CHECKPOINTS=2,\
MILESTONE_CHECKPOINT_STEPS=none \
  examples/bace_gigpo/run_alfworld_h100_2gpu_reference_aligned.sbatch \
  algorithm.bace.competence_threshold=0.60 \
  algorithm.gigpo.step_advantage_w=0.75 \
  algorithm.bace.batch_erv_threshold=0.010
```

若只改其中一个，例如只做 ERV threshold sweep，就只在最后加：

```bash
algorithm.bace.batch_erv_threshold=0.010
```

并仍为该 sweep 设置新的 `BACE_RUN_NAME`。这保证 checkpoint 自动恢复只发生在“同一方法、同一 seed、同一超参数”的重提作业中。

## 6. 先做 dry-run，再提交正式训练

建议先验证参数是否真的进入解析命令。dry-run 不申请 GPU、不启动 Ray 或训练，只写 metadata：

```bash
cd /hpcwork/xsz96350/fu_project/work-BACE/verl-agent-src

DRY_RUN=1 \
BACE_RUN_NAME=dry_c8_s1_comp60_w075_tau010 \
BACE_SEED=1 \
BACE_CREDIT_MODE=c8_macro_local_strict_ancestor \
BACE_SCHEDULING_PROFILE=optimized \
TARGET_STEP=1 \
examples/bace_gigpo/run_alfworld_h100_2gpu_reference_aligned.sbatch \
  algorithm.bace.competence_threshold=0.60 \
  algorithm.gigpo.step_advantage_w=0.75 \
  algorithm.bace.batch_erv_threshold=0.010
```

之后检查新生成的：

```text
experiments/alfworld-qwen2.5-1.5b-exact/run_metadata/<run-name>/...
  resolved_command.sh
  run_metadata.txt
```

必须在 `resolved_command.sh` 中确认四项：

```text
algorithm.bace.credit_mode=c8_macro_local_strict_ancestor
algorithm.bace.competence_threshold=<目标值>
algorithm.gigpo.step_advantage_w=<目标值>
algorithm.bace.batch_erv_threshold=<目标值>
env.seed=<目标 seed>
```

## 7. 续跑与 checkpoint 注意事项

- 对同一个实验重提交时，保持完全相同的 `BACE_RUN_NAME`、`BACE_SEED` 和三个关键超参数；脚本会从该 run 的最新完整 checkpoint 自动恢复。
- 启动前会清理旧进程遗留的 checkpoint 轮转视图；训练中保留最近 `MAX_CHECKPOINTS` 份（当前通常为 2）。
- 新的超参数组合、不同 seed 或不同 C8 逻辑必须使用新 run name，不能从旧 run 的 checkpoint 继续训练。
- `SAVE_FREQ=5` 控制常规 checkpoint 间隔。`MILESTONE_CHECKPOINT_STEPS=none` 是此前 C8 正式 run 的设置；若要额外保存特定 step，可设为例如 `10,75,100,140`，它们会保存到 `preserved_checkpoints/<run-name>/`，不受常规两份轮转影响。

## 8. 最小可复现实验清单

复现实有 C8 seed 0 的方法配置时，至少要保持：

```text
BACE_CREDIT_MODE=c8_macro_local_strict_ancestor
TREE_CREDIT_MODE=current
MACRO_NORMALIZATION_MODE=stable_occurrence
BACE_SEED=0
BACE_SCHEDULING_PROFILE=optimized
CAPACITY_CORRECTION_BATCH_SIZE=4
algorithm.bace.competence_threshold=0.5
algorithm.gigpo.step_advantage_w=1.0
algorithm.bace.batch_erv_threshold=0.005
TARGET_STEP=150
```

其中 `BACE_RUN_NAME` 可以不同；但若目标是精确续跑已有 C8 run，则它必须与原 run name 相同。
