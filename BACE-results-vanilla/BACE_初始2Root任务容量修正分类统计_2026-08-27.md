# 初始 2-root 任务的容量修正分类统计

日期：2026-08-27  
实验：`bace_alfworld_qwen2_5_1_5b_exact_rotation_fix_seed0`  
范围：正式 4×H100，训练 step 1–150

## 1. 结论

在本实验中，初始选择 2 条 natural root 的 task 一共有 **504 个**，占全部 2,400 个 task 的 **21.0%**。

其中：

- **304/504 个 task 发生过容量修正，占 60.32%**；
- 初始规划的 branch slot 共 3,024 个；
- 其中 1,276 个 branch slot 被转换为补充 root；
- 按 branch slot 计算的修正率为 **42.20%**；
- 发生修正的 task 平均补充 4.20 条 root；
- 发生修正的 task 最终平均有 6.20 条 root，中位数为 7 条，众数为 8 条。

因此，针对“初始只给 2 条 root”的任务，容量修正不是偶发现象，而是比较常见；但它并不表示算法错误。它表示 2 条 root 对当前 task 的可用 anchor/ERV 信息通常不足以支撑最初规划的 branch 数量。

## 2. 统计口径

正式配置为：

```text
total_leaf_budget = 8
min_natural_roots = 2
max_branches_per_anchor = 2
batch_erv_threshold = 0.005
```

因此当初始 `R_plan=2` 时，初始 branch quota 为：

```text
Q_plan = 8 - 2 = 6
```

一次容量修正执行：

```text
R <- R + 1
Q <- Q - 1
```

所以对于初始 2-root task：

```text
最终 root 数 = 2 + correction_count
最终 branch 数 = 6 - correction_count
```

本文中的：

- **task 修正率**：发生过至少一次修正的 task 数 / 初始 2-root task 总数；
- **slot 修正率**：被转换的 branch slot 总数 / 初始规划 branch slot 总数；
- **最终 root 数**：容量收敛并停止修正时的 `R`；
- **补充 root 数**：`correction_count`，即从 branch slot 转换来的 root 数。

|---|---:|---:|---:|---:|---:|---:|---:|---:|

### 3.1 主要现象

`pick-and-place` 是最明显的异常来源：

- 254 个初始 2-root task 中有 181 个发生修正；
- task 修正率 71.26%；
- 补充 825 条 root，占所有初始 2-root 修正 root 的 64.67%；
- 181 个修正 task 中有 97 个最终补到 8 条 root。

相比之下，`pick-two-and-place` 没有初始 2-root task，说明该 family 的 readiness/规划分布在本次 run 中没有进入这种最激进的 `Q_plan=6` 情形。

### 4.1 全部初始 2-root 且发生修正的 task

304 个修正 task 的最终 root 数如下：

|---:|---:|---:|---:|
| 3 | 1 | 53 | 17.43% |
| 4 | 2 | 33 | 10.86% |
| 5 | 3 | 21 | 6.91% |
| 6 | 4 | 28 | 9.21% |
| 7 | 5 | 32 | 10.53% |
| 8 | 6 | **137** | **45.07%** |
| **合计** | — | **304** | **100%** |

直接回答“通常修正到多少条 root 才停止”：

- 最常见是修正到 **8 条 root**，占 45.07%；
- 中位数是 **7 条 root**；
- 55.59% 的修正 task 最终达到 7 或 8 条 root；
- 平均最终为 6.20 条 root；
- 平均补充 4.20 条 root；
- 最常见的补充次数是 6 次，即从 `R=2,Q=6` 修正到 `R=8,Q=0`。

`pick-and-place` 不仅修正率最高，而且最终到达 8-root 的比例也最高：97/181 = 53.59%。这说明该 family 的初始 readiness 经常给出较高 branch quota，但 2 条 root 产生的实际局部 capacity 不足。

## 5. 按容量修正原因分类

对每个初始 2-root 且发生修正的 task，令：

- `A`：首次检查得到的 structural anchor 数；
- `C`：首次检查得到的 information capacity；
- `Q_plan=6`：初始 branch quota；
- `2A`：在每个 anchor 最多支持 2 个 branch 时的结构理论上限。

分类如下：

| 原因 | 判定 | task 数 | 占修正 task | 补充 root slot | 占补充 root |
|---|---|---:|---:|---:|---:|
| 无 structural anchor | `A=0` | 61 | 20.07% | 318 | 24.92% |
| 结构 anchor 上限不足 | `A>0` 且 `2A<Q_plan` | 147 | 48.36% | 616 | 48.28% |
| ERV 边际容量不足 | `2A>=Q_plan` 但 `C<Q_plan` | 96 | 31.58% | 342 | 26.80% |
| **合计** | — | **304** | **100%** | **1,276** | **100%** |

因此初始 2-root 修正中：

- 约 68.4% 的 task 至少存在明显的结构 anchor 不足（无 anchor 或结构上限不够）；
- 约 31.6% 的 task 结构 anchor 数量原则上够，但部分 branch 的边际 ERV 没有达到 `0.005`；
- 对 branch slot 而言，结构类原因占 73.2%，ERV 边际原因占 26.8%。

### 5.1 这里的“anchor 不足”是什么意思

不是简单地说 root 数量少，而是 2 条 root 没有产生足够多的可比较前缀：

```text
同一 anchor 前缀
    + 至少两个不同 action
    + 可以建立局部 action posterior
    -> 才是 structural anchor
```

如果只有一个 action，或者 root 前缀彼此完全不同，就无法从该位置构造 Batch-ERV branch。

### 5.2 这里的“ERV 过小”是什么意思

anchor 已经存在，但新增 branch 的预期信息增益低于阈值：

```text
delta_1 < 0.005 或 delta_2 < 0.005
```

这通常表示：

- action posterior 已经比较确定；
- 不同 action 的成功概率差异不足以产生足够信息价值；
- 第二个 branch 的边际价值尤其容易下降。

它不是 ERV 计算失败，而是当前局部 posterior 下继续 branch 不值得超过设定阈值。

## 6. 典型 task 示例

### 6.1 ERV 不足但 anchor 数够：step 58

task：`pick-and-place:b1cd64e7`

```text
初始：R=3,Q=5（该 task 并非初始 2-root，仅作为 ERV 机制示例）
首次 capacity：A=5
anchor capacities=[0,0,0,1,2]
C=3
```

`2A=10`，结构上限足够，但只有 3 个 branch slot 的 marginal ERV 通过阈值，最终补充 2 条 root 后保留 3 个 branch。这说明 ERV 不足可以独立于 anchor 数量发生。

### 6.2 结构 anchor 上限不足：step 81

task：`pick-and-place:cebb9be2`

```text
初始：R=2,Q=6
首次：A=1，capacity=[2]，C=2
```

即使唯一 anchor 达到每 anchor 的最大 capacity 2，也只有 2 个 branch slot，远低于 `Q_plan=6`。该 task 最终补 6 条 root，变为 `R=8,Q=0`。

### 6.3 完全没有 structural anchor：step 81

task：`pick-and-place:516881d6`

```text
初始：R=2,Q=6
首次：A=0,C=0
```

2 条 root 没有形成“同一前缀下至少两个 action”的比较结构。后续追加 root 后曾出现 anchor，但 capacity 仍可能再次变为 0；最终补 4 条 root，保留 2 个 branch。

### 6.4 有 anchor 但所有 ERV 都低：step 136

task：`pick-and-place:661d99d5`

```text
初始：R=2,Q=6
首次：A=6
anchor capacities=[0,0,0,0,0,0]
C=0
```

这里不是没有 anchor，而是 6 个 anchor 的 `delta_1` 最大约为 `0.004467`，全部低于 `0.005`；`delta_2` 也全部低于阈值。因此最终仍补到 `R=8,Q=0`。

## 8. 是否说明初始选择 2 条 root 不合理

不能简单地说 2 条 root 本身错误。它是正式配置允许的最小 natural-root 数量，具有明确的探索/branch 预算权衡：

- root 少，理论上可以做更多 branch；
- branch 可以用于同一 anchor 下的 action credit 信息获取；
- 如果实际 anchor 不足，capacity correction 会安全地把 branch slot 转回 root。

本次数据说明的是：对 `pick-and-place` 等 family，使用 family-level readiness 直接推到 `Q=6` 过于乐观，导致 correction 频繁。容量修正保住了正确性，但增加了追加 root wave。

## 9. 建议

### 9.1 必须保留

- capacity correction；
- `R+Q=8` 约束；
- Exact Batch-ERV capacity check；
- packed root generation；
- selected-worker branch execution；
- Replay validation；
- occurrence-level PPO credit。

不能为了降低修正率而强行执行全部 `Q_plan=6`，否则会出现 branch quota 超过真实 capacity 的非法请求。

### 9.2 推荐先做的低风险工作

记录每个初始 2-root task 的：

- `Q_plan`、`R_plan`；
- 首次 `A`、`C`；
- 每个 anchor 的 action 数；
- 每个 anchor 的 `delta_1/delta_2`；
- 原因标签 `no_structural_anchor`、`anchor_ceiling`、`erv_below_threshold`；
- 每轮 `R/Q/C/A`；
- family-level correction wave 和耗时。

这样可以区分“root 多样性不足”和“ERV 已经太小”，而不是只看到最终补了几条 root。

### 9.3 推荐的算法方向

利用历史 step 的 family-level capacity 做 lagged、保守的 quota 预测：

```text
C_hat = lagged family capacity estimate
Q_plan = min(round(6 * readiness), conservative_capacity_quantile(C_hat))
R_plan = 8 - Q_plan
```

仍保留现有 capacity correction 作为安全网。建议先对已有 150-step trace 离线评估，确认能否降低 correction ratio，再进行小规模 A/B profile。

## 10. 最终答案

对于初始选择 2 条 root 的任务：

```text
task 修正率       = 60.32%
branch slot 修正率= 42.20%
```

对于发生容量修正的这类任务：

```text
平均最终 root = 6.20
中位数最终 root = 7
众数最终 root = 8
最常见情况 = 从 2 条补到 8 条 root
```

所以最准确的概括是：

> 初始 2-root task 中，约六成会触发容量修正；一旦触发，通常会增加到 7–8 条 root 才停止，最常见是补满到 8 条。主要原因是当前 root 产生的 structural anchor 数量不足或结构容量不够，约三成则是 anchor 数量原则上够但边际 ERV 低于 `0.005`。
