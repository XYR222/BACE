# C0 / C1 / C2 正式实验结果与 C2 诊断（2026-09-02）

## 1. 结论摘要

本次比较包含三条 2×H100、seed 0、从 step 0 训练至 step 150 的 BACE ALFWorld 实验。三条训练均完成了 150 个 policy update，保存了 step 150 checkpoint 和 BACE trace artifact。C0 与 C1 的最终 validation success 接近（89.8% 与 89.1%）；C2 为 77.3%，低约 12.5 个百分点。

当前证据支持以下判断：

1. C2 的较低 validation 不是 GPU、OOM、Replay 失败、branch worker 选择失败或 Exact Batch-ERV 约束失效造成的。
2. C2 使用的 `stopping` 是实质性的算法干预：它会更早停止 pairwise branch acquisition，并用 one-way fallback root 填回叶子预算；这改变了 root/branch 训练数据组成。当前单 seed 结果显示该策略在 `tau=0.005` 下不如 C0/C1。
3. C2 存在一个已确认的 fallback-root 谱系/计量缺陷：fallback root 没有写入 `source_type="root"` 和 `leaf_id`，因而 artifact 中显示为 `source=None`。该缺陷污染 root/branch/mixed 诊断统计，但不参与当前 advantage/PPO 计算，不能解释 validation 差距。应在后续 C2 实验前修复，但不能回溯改变本次训练的梯度或 validation。
4. 这是每个方法一个 seed 的结果，足以否定“C2 在本配置下明显更优”的假设，但不足以作跨 seed 的统计显著性结论。

## 4. 三种方法的语义差异

### C0：Full Exact Batch-ERV

C0 使用历史的单轮 `full` 模式。root 执行后，coordinator 一次冻结并执行本 update 的 branch 请求；不会启用 pairwise fixed/stopping 的后续 acquisition 轮次，也不会产生 stopping fallback root。

其目标是作为完整 Exact Batch-ERV 主线的对照：在每个任务严格维持最终 `R+Q=8`，但 branch 数由一次全局分配决定。

### C1：Pairwise Fixed

C1 使用 `pairwise.mode=fixed`，pairwise batch size 为 2。它在冻结的全局 branch 计划下进行固定的多轮 pairwise acquisition；本次训练中，后期通常执行 3 轮。C1 不允许 fallback root：如果尚有计划 branch，就通过固定流程继续完成 branch evidence。

这使 C1 在后期保持略高的 branch 密度与 branch credit 比例，但 rollout 总成本也最高。

### C2：Pairwise Stopping

C2 使用 `pairwise.mode=stopping`，同样以 batch size 2 执行 pairwise acquisition。它在每轮后根据 posterior / threshold capacity 判断某任务是否还值得继续申请 branch。对被提前停止的 branch 位，不再强行补 branch，而是以 one-way packed fallback root 补足该任务的最终 8 个 leaf。

因此 C2 同时保持两个不变量：

- 每个任务最终仍满足 `R + Q = 8`；
- 不会把不满足 stopping 条件的 branch 当作已获得的 branch evidence。

但它改变了训练分布：较少 branch、较多 root，尤其在训练早期 competence 较低、可形成的 pairwise evidence 较少时更明显。

## 7. C2 的数据组成与诊断

### 7.1 Branch / fallback 的量化差异

| 全程均值（每 step） | C0 | C1 | C2 |
| --- | ---: | ---: | ---: |
| final branches | 39.46 | **41.23** | 36.33 |
| pairwise branch rounds | 0.99 | **2.40** | 2.33 |
| branch trainable occurrences | 645.8 | **690.0** | 639.6 |
| root trainable occurrences（标签为 root） | 2948.4 | 2977.2 | 3435.5 |
| fallback roots | 0 | 0 | **9.67** |
| rollout total time | 242.5 s | 313.9 s | 270.3 s |

C2 共执行了 706 条 fallback root。尤其在最初 10 个 update，C2 平均只有 1.9 条 branch，而 C0/C1 为 3.8/3.6 条。这个早期数据构成差异会改变 action-level local credit 的可用对比证据，之后的训练轨迹不再应预期与 C0/C1 完全重合。

从机制上看，C2 的 stopping policy 的目的就是在证据不足时避免继续 branch；本次结果说明该保守决策在当前 `tau=0.005`、单 seed、150 step 预算下带来了较弱的后期学习表现。它是一个需要通过多 seed 与阈值消融继续检验的方法结论，而不是已确认的执行错误。

### 7.2 已确认的 fallback-root 谱系计量缺陷

在 `rollout_collector.py` 中，普通 root batch 会在 branch 前通过 `_set_lineage(..., "root", ...)` 写入 `source_type` 和 `leaf_id`。C2 的 fallback root 在 branch 后生成并 append 到总 batch，但 `_collect_pairwise_fallback_roots()` 返回前没有执行同样的谱系写入。

结果是 C2 artifact 的 trainable occurrence 来源累计为：

| `source_type` | occurrence 数 |
| --- | ---: |
| `root` | 515,322 |
| `branch_origin` | 5,498 |
| `branch_suffix` | 90,444 |
| `None`（fallback root） | **7,488** |

这 7,488 条 `None` 与 706 条 fallback root 的数量和轨迹长度一致，是 fallback root 未标记的直接证据。

影响边界：

- 会影响 `root_success_rate`、`branch_success_rate`、`mixed_success_rate` 的来源分类，以及 trace/credit 的按来源诊断；C2 的 root 指标因此低估或被混合分类。
- 不影响环境执行、terminal reward、Replay、最终 `R+Q=8`、PPO batch 拼接，或 validation。
- 当前 `compute_bace_gigpo_advantage()` 不依据 `source_type` 计算 macro/local advantage；`source_type` 在该路径仅用于诊断统计。因此这不是 C2 低 validation 的梯度计算根因。

后续修复应在 fallback root 收集完成后、加入总训练 batch 前，使用与普通 root 相同的 `_set_lineage` 规则，为每个 fallback trajectory 写入 `source_type="root"` 及稳定 `leaf_id`。修复后的 C2 应从 step 0 新开 run，不能将新旧谱系规则混在同一恢复链中。

## 8. 对 C2 较差结果的最终判断

目前没有发现能够把 C2 的 77.3% “纠正回” C0/C1 水平的执行或硬件 bug。更合理的解释是：

1. stopping policy 在早期减少了 branch evidence；
2. 它以 fallback root 维持叶子预算，但 fallback root 不是 branch 对比证据的等价替代；
3. 这使 C2 在本次预算内形成了不同的学习轨迹，并在 step 100 后明显落后；
4. fallback-root 的缺失来源标签是分析质量问题，需要修复，但不会改变已完成 run 的 PPO 更新与 validation 分数。

因此，本次单 seed 结果的保守结论是：在当前配置下，C1 fixed 与 C0 full 均优于 C2 stopping；C2 不应被作为默认线上方案，除非完成谱系修复后在多个 seed 上重新验证，并显示出成本或效果方面的可重复优势。
