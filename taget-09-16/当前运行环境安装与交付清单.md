## 5. 从零安装

以下命令是与当前环境对齐的重建起点。CUDA 扩展必须在目标 GPU/CUDA 栈上重新验证，不保证在不同 GPU 型号或不同驱动上字节级一致。

```bash
module purge
module load GCCcore/13.3.0
module load CUDA/12.8.0

source /home/<user>/miniforge3/etc/profile.d/conda.sh
conda create -p /hpcwork/<account>/<user>/verl-agent python=3.12 -y
conda activate /hpcwork/<account>/<user>/verl-agent

pip install vllm==0.11.0
pip install flash-attn==2.7.4.post1 --no-build-isolation --no-cache-dir

cd <workspace>/work-BACE/verl-agent-src
pip install -e .

pip install \
  gymnasium==0.29.1 \
  stable-baselines3==2.6.0 \
  alfworld==0.4.2 \
  tensorboard==2.20.0 \
  pytest==9.1.1

python -m pip check
```

不要在当前已验证 prefix 中直接执行 `pip install -r requirements.txt` 或随意升级 torch、vLLM、xFormers、FlashAttention、Transformers。仓库 requirements 是开发范围依赖，不等于本次二进制环境锁文件。需要实验新版本时，应创建新的独立 prefix 并重新 smoke。

## 6. 每次作业的环境准备

```bash
module purge
module load GCCcore/13.3.0
module load CUDA/12.8.0

source /home/<user>/miniforge3/etc/profile.d/conda.sh
conda activate /path/to/verl-agent

unset ROCR_VISIBLE_DEVICES HIP_VISIBLE_DEVICES
unset VLLM_ATTENTION_BACKEND
export VLLM_USE_FLASHINFER_SAMPLER=0
export ALFWORLD_DATA=/path/to/alfworld
export HF_DATASETS_OFFLINE=1
export HF_HUB_OFFLINE=1
export PYTHONNOUSERSITE=1
export TOKENIZERS_PARALLELISM=false
```

`GCCcore/13.3.0` 用于提供 TextWorld/Fast Downward 所需的新 C++ runtime。当前 H100/vLLM 0.11.0 环境不强制 XFormers attention backend；让 vLLM 自动选择兼容的 CUDA backend。若目标机器不是 H100，应重新验证 attention backend，而不是照搬结论。

BACE 启动器还会限制 OpenMP/BLAS/Rayon 线程，并为每个作业使用独立的节点本地 Ray 临时目录。不同作业不得共享 Ray head、`TMPDIR` 或 `RAY_TMPDIR`。

## 7. GPU 节点验证

登录节点没有 GPU，加载 CUDA 后出现“node does not have a GPU”警告是正常的；以下检查必须在调度器分配的 GPU 节点中运行：

```bash
nvidia-smi -L
python - <<'PY'
import torch, vllm, xformers
print("torch=", torch.__version__)
print("torch CUDA=", torch.version.cuda)
print("CUDA available=", torch.cuda.is_available())
print("GPU count=", torch.cuda.device_count())
print("vLLM=", vllm.__version__)
print("xFormers=", xformers.__version__)
PY
```

必须看到两张目标 GPU，并执行：

1. C0 入口 `DRY_RUN=1`，检查完整 resolved command；
2. 一个真正的 1-step H100 smoke；
3. smoke 达到 `training/global_step:1`、退出码 0；
4. BACE smoke 的 trace validation 为 `ok=true`；
5. GiGPO smoke 无 CUDA OOM、Ray actor death 或 ALFWorld reset 错误。

只有这些检查通过后，才能提交正式 39 组实验。

- TensorBoard event；
- W&B 本地运行目录、cache 和 artifact staging；
