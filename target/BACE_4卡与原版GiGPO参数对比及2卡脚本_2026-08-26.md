# BACE 4 卡与原版 GiGPO 参数对比及 2 卡入口

> **状态提示（2026-08-27）：原集群参数记录。** 本文用于解释历史 4 卡/2 卡 run，不是新设备配置入口。换设备使用 [`docs/02_新设备安装与首次运行.md`](../docs/02_新设备安装与首次运行.md)，判断方法参数使用 resolved command 和 [`docs/09_逻辑模式与兼容边界.md`](../docs/09_逻辑模式与兼容边界.md)。

## 对比口径

- 当前 4 卡 BACE：作业 `3116958` 的实际解析命令，而不只看 wrapper 默认值。
- 原版 GiGPO：`AFH/examples/gigpo_trainer/run_alfworld.sh`，以及该脚本未显式覆盖时使用的 `ppo_trainer.yaml` 默认值。
- 新 2 卡 BACE：`examples/bace_gigpo/run_alfworld_h100_2gpu_reference_aligned.sbatch`。

## 有效差异

| 参数 | 当前 4 卡 BACE `3116958` | 原版 2 卡 GiGPO | 新 2 卡 BACE |
|---|---:|---:|---:|
| GPU 数 | 4 | 2 | 2 |
| advantage estimator | `bace_gigpo` | `gigpo` | `bace_gigpo` |
| Exact tie-break identity | `legacy_uuid`（兼容当前 run） | 不适用 | `stable_v1` |
| PPO micro batch / GPU | 16 | 32 | 32 |
| rollout/ref log-prob micro batch / GPU | 16 | 32 | 32 |
| rollout tensor parallel | 1 | 2 | 2 |
| `max_num_batched_tokens` | 16384 | 8192（默认） | 8192（显式） |
| `max_num_seqs` | 128 | 1024（默认） | 1024（显式） |
| actor torch compile | false | true（默认） | true（显式） |
| validation before training | false | true | true |
| validate at last step | false | true（默认） | true（显式） |
| logger | console + TensorBoard | console + W&B | console + W&B |
| checkpoint frequency | 5 | 不保存 | 5 |
| resume | auto | 无 | auto |
| checkpoint retention | 2（作业 `3116958` 实际值） | 无 | 1--2，默认 1 |
| vLLM attention backend | 自动选择 | 强制 XFORMERS | 自动选择 FLASH_ATTN |
| Ray CPU 上限 | 64 | 未显式设置 | 32 |

当前 4 卡的 micro batch 16 来自作业 `3015027` 的实测：32 在 actor update 阶段发生 CUDA OOM，16 成功。`16384/128` 是旧 H100 BACE launcher 的显式调度配置，并不是该 PPO OOM 的修复。

新 2 卡入口恢复原版 GiGPO 的 `micro=32`、`TP=2`、`8192/1024`、torch compile 和 validation 行为。先前 2 卡 branch gate `3095842` 已经证明这组核心配置能完成一个带 branch 的训练 step。

## BACE 专属配置

这些参数在原版 GiGPO 中不存在，是新旧 BACE 入口必须保留的方法差异：

| 类别 | 配置 |
|---|---|
| 方法 | Exact Batch-ERV、dynamic、staged、packed |
| branch 执行 | selected-worker、active compaction |
| budget | `B=8`、`R_min=2`、每 anchor 最多 2 branch |
| competence | threshold `0.5` |
| family prior | 初始均值 `0.10`、strength `2.0` |
| history | decay `0.8`、transfer `0.1`、strength `[2,8]` |
| local prior | strength `2.0` |
| Batch-ERV | threshold `0.005`，tie tolerance `1e-12/1e-10` |
| credit | strict identity、occurrence credit |
| replay | action-set comparison、最多一次 origin retry |
| artifacts | token arrays、trace validation、family-history checkpoint state |

新 2 卡入口启用 `stable_v1`：UUID 继续作为 lineage 唯一标识，但
Exact 全局 allocation、局部 action plan 和 replay origin 的 tie-break 使用
`policy_update_id + task_batch_index + environment_reset_key` 派生的稳定身份。
该模式写入 checkpoint 参数签名，禁止与旧 `legacy_uuid` checkpoint 混合恢复。

## 仅为集群运行增加的差异

新 2 卡脚本每 5 step 保存一次 checkpoint，并在跨 Slurm 作业恢复前识别和轮转旧 checkpoint；这是为了适应 24 小时 wall-time，不改变 PPO 或 BACE 数学。默认只保留最新 1 份，可在空间充足时设置 `MAX_CHECKPOINTS=2`。

原版强制 `VLLM_ATTENTION_BACKEND=XFORMERS`。当前环境的 vLLM 0.11.0 在 H100、TP=2 的 V1 XFormers decode 路径上出现过 KV-cache 构建错误，因此新脚本取消该环境变量，让 vLLM 选择 FLASH_ATTN。这是必要的运行时兼容例外。

## 使用方式

只解析并检查命令，不训练：

```bash
DRY_RUN=1 bash examples/bace_gigpo/run_alfworld_h100_2gpu_reference_aligned.sbatch
```

提交正式 2 卡作业：

```bash
sbatch examples/bace_gigpo/run_alfworld_h100_2gpu_reference_aligned.sbatch
```

提交独立的一步 smoke（使用独立 run name，避免污染正式 checkpoint）：

```bash
sbatch --export=ALL,TARGET_STEP=1,SAVE_FREQ=1,MAX_CHECKPOINTS=1,\
BACE_RUN_NAME=bace_2gpu_reference_smoke_seed0 \
examples/bace_gigpo/run_alfworld_h100_2gpu_reference_aligned.sbatch \
trainer.test_freq=-1 trainer.val_before_train=false trainer.validate_on_last_step=false
```

不要让 smoke 和正式训练使用同一个 `BACE_RUN_NAME`。
